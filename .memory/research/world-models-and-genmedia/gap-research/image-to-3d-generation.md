# Image-to-3D and Text-to-3D Asset Generation — Research

Research date: 2026-09-16. Focus: the common denominator across explored media platforms (TripoSR, TripoSG, TRELLIS.2, Hunyuan3D) — model landscape, technical approaches, game-engine asset prep, and internal Amazon prior art.

## Summary

Image/text-to-3D asset generation has, over 2024–2026, converged on **two-stage pipelines**: (1) a shape/geometry generator, then (2) a separate texture/PBR-material generator conditioned on the shape [L4:established, Hunyuan3D-2 paper; IML-Australia wiki]. Two architectural families dominate:

- **Native-3D generative models** — a 3D VAE compresses shapes into latent tokens, then a diffusion/flow transformer (DiT) generates in that latent space directly from an image embedding. Examples: Hunyuan3D-DiT, TripoSG, Microsoft TRELLIS (via its Structured LATent "SLAT" representation) [L1:verified, arXiv 2501.12202, 2502.06608, 2412.01506].
- **Feed-forward reconstruction (LRM-style)** — a single forward pass regresses a triplane/implicit field from one image, meshed via marching cubes; fastest but lower fidelity. Examples: TripoSR (~0.5 s on A100), Stable Fast 3D (0.3–0.5 s) [L1:verified, arXiv 2403.02151, 2408.00653].

The frontier (late 2025 / 2026) is **TRELLIS.2** (4B params, "field-free" O-Voxel sparse structure, full PBR) and **Hunyuan3D-2.1/2.5** (production-ready PBR via multi-view Paint model) [L1:verified, HF microsoft/TRELLIS.2-4B; arXiv 2506.15442]. Licensing splits sharply: TRELLIS and TripoSR/TripoSG/Stable Fast 3D are **MIT/permissive**; Hunyuan3D is under a **restrictive Tencent non-commercial/community license** with territorial carve-outs (EU/UK/South Korea excluded) [L2:verified, HF LICENSE files].

Amazon has multiple active internal efforts: the **IML-Australia "Generate 3D assets from product images"** project (a CLAY-like two-stage generative model finetuned on Amazon data, targeting Bedrock hosting via the AGI team) [L4:verified, w.amazon.com wiki]; **VTO/Fashion Innovation** 2D-catalog-to-3D for "View in 3D"/AR; a **GDC 2025 games demo** that generated in-game 3D assets with TRELLIS + Tencent models via SageMaker; and mature **3D Digital Studio** artist SOPs (PBR validation, GLB export, Woodshop QA) that define what "game/CX-ready" means internally.

## Technical approaches

**1. Native-3D latent generation (the dominant high-fidelity path).**
Stage A compresses 3D shapes into a compact latent with a **3D VAE / ShapeVAE**. TripoSG and the Amazon IML project both use the **3DShape2VecSet** latent representation, with importance sampling on mesh surfaces to capture fine detail; TripoSG's VAE uses a **hybrid SDF + normal + eikonal** loss [L1:verified arXiv 2502.06608; L4 IML-Australia wiki]. Stage B is a **rectified-flow / flow-matching diffusion transformer (DiT)** that generates latent tokens conditioned on the input image [L1:verified]. Geometry is extracted from the decoded field via **marching cubes** (or differentiable meshing like FlexiCubes) [L1:verified arXiv 2404.00987].

**2. Structured LATent (SLAT) — TRELLIS.** A sparsely-populated 3D voxel grid where each active voxel carries **dense multiview visual features from a vision foundation model**; a rectified-flow transformer generates the SLAT, which can then be **decoded to radiance fields, 3D Gaussians, or meshes** — one latent, multiple output formats [L1:verified microsoft.com Research workbench; arXiv 2412.01506]. TRELLIS.2 replaces the field-based SLAT with a **"field-free" O-Voxel** sparse structure for sharper features and complex topology at 4B params [L1:verified HF microsoft/TRELLIS.2-4B].

**3. Multi-view diffusion + sparse-view reconstruction (the LRM-adjacent path).** A 2D diffusion model (often a finetuned image diffuser) generates **multi-view-consistent images** (sometimes RGB-D, or paired color + normal maps) from one input; a feed-forward reconstruction model fuses them into 3D. Consistency is the core challenge — approaches use depth-guided attention (MVD-Fusion), cross-domain color+normal diffusion (Wonder3D), or multi-view conditioning (Magic-Boost) [L1:verified arXiv 2404.03656, 2310.15008, 2404.06429]. Downsides: view inconsistency and over-smoothed geometry, often needing a distillation/refinement pass [L1:verified arXiv 2404.03656].

**4. Feed-forward LRM (fastest).** TripoSR regresses a triplane-based implicit representation in a single forward pass (no per-scene optimization), meshed with marching cubes — draft mesh in ~0.5 s [L1:verified arXiv 2403.02151]. SF3D adds an explicit mesh head, **fast UV unwrapping**, **illumination disentanglement (delighting)**, and material-parameter + normal-map prediction so output is directly game-usable [L1:verified arXiv 2408.00653].

**5. Gaussian splatting / radiance fields as an output format.** SLAT and Triposplat can decode to **3D Gaussians** for novel-view synthesis / fast preview, distinct from mesh output for artist/game pipelines [L1:verified arXiv 2412.01506; L4 LunAI catalog `tripo3d/triposplat`].

**6. Image conditioning — DINO features.** The image is encoded by a vision foundation model and injected into the DiT as the conditioning signal. Amazon's IML project uses **DINO-v2** features (and naively averages them for multi-image conditioning — flagged as improvable) [L4:verified IML-Australia wiki]. TRELLIS.2 uses **DINOv3** (a gated dependency) plus RMBG-2.0 for background removal [L1:verified HF microsoft/TRELLIS.2-4B].

**7. Texture / PBR decoupling.** Because geometry and texture are generated in separate stages, PBR maps (albedo/diffuse, roughness, metallic, normal/height) are produced **conditioned on the finished shape** — enabling artists to retouch the shape before texture baking, and to regenerate multiple texture variants [L4:verified IML-Australia + Hunyuan3D-Paint; L1 arXiv 2501.12202]. Hunyuan3D-Paint and Hunyuan3D-2.1's PBR path generate **multiple orthogonal multi-view RGB albedo maps** that are baked into a UV texture [L1:verified arXiv 2506.15442; L4 IML-Australia].

## Game-engine asset prep

AI-generated meshes are almost never engine-ready as-emitted. The consistent industry checklist (Tripo, Customuse, community guides) [L6:established across multiple 2026 guides]:

- **Retopology.** Generators emit dense **triangulated "blob mesh"** with no clean edge flow; it "deforms like melting plastic" when animated. Retopologize to a **quad-dominant** mesh with sensible edge loops (esp. for deforming parts) [L6:reported tripo3d.ai "auto-rig", "fix-ai-3d-triangle-soup"].
- **Polygon budget / LODs.** Reduce polycount to a game-appropriate level; author multiple **LOD** levels [L6:established customuse.com, ourcodeworld.com].
- **UVs + texel density.** AI meshes often ship with no UVs → **re-UV**; check consistent texel density [L6:reported tripo3d checklist; matches Amazon KRYTEN UV-unwrap training below].
- **PBR material correction.** AI textures need correction to valid PBR value ranges and artifact removal; separate into proper **albedo/roughness/metallic/normal** channels [L6:reported; L4 Amazon 3D Digital Studio SOP mandates PBR-safe value clamps — colors not >0.85 or <0.02].
- **Scale, pivot/origin, naming conventions** — normalize before import [L6:established].
- **Collision.** Author collision geometry (rarely usable from the raw mesh) [L6:established].
- **Export format.** **GLB/glTF** (with embedded PBR) is the common web/engine interchange; FBX and USD/USDZ for Unreal/AR; note glTF spec **excludes lights/cameras** on export — a known gotcha [L6:established ourcodeworld.com; matches this project's `bake-export-oracle` note].
- **Rigging/animation** where relevant — Meshy offers auto-rig; Tripo offers built-in retopology [L4:verified LunAI catalog; L6 customuse.com].

Amazon's own bar (3D Digital Studio "3D Artist SOP" / KRYTEN training) codifies this: **PBR validate** smart material + **PBR Safe Clamp** filter in Substance Painter, **Woodshop 2 GLB viewer** pre-check (Ambient mode for color vs reference, Neutral mode for metallic/roughness), and QA checks for dimensions accuracy, gaps between faces, floating geometry, backfaces, and low texel density [L4:verified w.amazon.com 3D_Digital_Studio/TRB_3D_SpecialProjects; KRYTEN_Softline_IP]. The KRYTEN Softline plan explicitly teaches: cleanup scanned mesh in ZBrush → **retopology in Maya** → UV unwrap (ZBrush UV Master + Maya, texel density) → texturing (Agisoft/Substance) → **GLB export combining OBJ + maps** → self-QA checklist → optimization/package upload [L4:verified KRYTEN_Softline_IP wiki]. The Fast-Retouch SOP details PBR texture baking (normal/roughness/AO) in Substance Sampler at 4096×4096 [L4:verified Fast_Re-touch_SOP wiki].

## Open questions

1. **Licensing for internal/commercial use.** TRELLIS/TripoSR/TripoSG/SF3D are MIT/permissive, but Hunyuan3D is Tencent-non-commercial with EU/UK/KR territorial exclusion — does any Amazon production use of Hunyuan3D (Shopbop pipeline, GDC demo) have a commercial-terms clearance? Not confirmed in sources. The nvdiffrast/NVIDIA dependency in TRELLIS may also carry non-commercial terms even though TRELLIS itself is MIT [L5 GitHub issue #22].
2. **Is there an AWS/Bedrock-native 3D generation offering?** IML-Australia targets Bedrock hosting via the AGI team ("establish dialogue regarding hosting text-to-3D/image-to-3D on Bedrock"), but no launched Bedrock 3D model surfaced in search — status unknown [L4, aspirational in the wiki].
3. **What are Amazon's internal texel-density / poly-budget / LOD numerics** for game (vs retail CX) assets? The 3D Digital Studio SOP gives PBR value clamps and 4K textures for retail; game-specific budgets (poly counts, LOD ratios, collision authoring) were not found internally — likely differ from the retail "View in 3D" bar.
4. **Multi-image conditioning.** IML notes naive DINO-v2 feature averaging for multi-image input is suboptimal; the better approach (cross-attention over per-view tokens, camera-pose conditioning) is an open research/eng item internally.
5. **Retopo automation maturity.** Commercial tools (Meshy remesh, Tripo retopo) claim quad-dominant output, but independent quality vs. hand-retopo for animation/deformation is unquantified in the sources gathered.
6. **Gaussian-splat vs mesh for the target use case** — SLAT/Triposplat can emit Gaussians (great for preview/novel-view) but game/AR pipelines need meshes; the conversion cost and quality tradeoff wasn't quantified here.
