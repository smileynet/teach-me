## Purpose

This is a **research + spike project to design and prototype a benchmark for gameplay world models** — AI systems that learn interactive, physics-aware simulations of environments from video/data (Google Genie, NVIDIA Cosmos, Roblox Cube, Decart Oasis, etc.) (`AGENTS.md` "Project Focus"; `.memory/CONTEXT.md` "Purpose"). Its central deliverable is the missing **eval-metrics** piece for a world-model story on AWS: a **Fidelity Divergence Score (FDS)** whose *behavioral* axis can tell "looks-real" apart from "plays-correctly" by scoring a model's rollout against a deterministic engine oracle (`docs/games-wmlbench-proposal.md` "Why this matters", §1). It is explicitly a docs/research project with no build system — work status lives in `tkt` tickets, not a PLAN.md (`AGENTS.md` "Commands", "Workflows").

## World Model Concepts

- **World model definition used here:** an AI system that learns to simulate interactive environments, predicting future states given actions — modeling spatial/physical dynamics, not text; explicitly *not* a hard-coded game engine (`.memory/CONTEXT.md` glossary).
- **Six-way architectural taxonomy** (`.memory/world-models-synthesis.md` "Architectural Taxonomy"): (1) **Video-latent space** — autoregressive/diffusion frame prediction conditioned on actions (Genie, Cosmos, Oasis, Odyssey, Runway); (2) **3D-native** — meshes/Gaussian splats (Roblox Cube, World Labs, Tencent HY-World); (3) **Hybrid engine + world model** (Roblox Reality); (4) **Latent-dynamics RL-native** (Dreamer v3, DIAMOND, TD-MPC2); (5) **Joint-Embedding Predictive / JEPA** (Meta V-JEPA 2, LeCun) — non-generative; (6) **Action foundation models** (General Intuition).
- **The benchmark's core hypothesis:** a genre-specific world model trained on engine-replay data can be scored against the engine oracle with an FDS whose **behavioral axis separates dynamics-corrupt from realism-corrupt clips** — the documented "ranking-reversal" (a model wins visual metrics like FVD while losing action-following) (`docs/games-wmlbench-proposal.md` §1). Falsifiable H0/Ha form with independent variable = which construct a clip violates, dependent = behavioral FDS.
- **Engine as oracle (games' advantage over robotics):** "reality" is the game engine re-simulating the identical seed frame + action sequence — a deterministic, bit-reproducible ground truth, not a physical camera (`.memory/CONTEXT.md` "Reality stream"; `docs/games-wmlbench-proposal.md` §3 Phase 2). This is why pixel error becomes a valid behavioral signal — the highest-risk dependency (Spike 0 determinism, `docs/games-wmlbench-proposal.md` §5, §6).
- **Four-part measurement backbone** implemented in `tools/fds_harness.py`: (1) **visual-fidelity axis** (PSNR/LPIPS — *reported, NOT trusted for behavior*); (2) **behavioral axis** — action-following via **IDM round-trip** (macro-F1 over discrete action channels + camera L1 — *trusted*); (3) **drift-over-horizon** — per-step error curve + maximum admissible horizon `h*`; (4) **action-sensitivity guard** — rollouts under different actions must diverge, catching an action-agnostic model that "wins" by replaying a plausible future (`tools/fds_harness.py` module docstring, `compute_fds`, `action_sensitivity`).
- **IDM round-trip:** the trusted behavioral metric re-infers actions from the model's generated frames using an Inverse Dynamics Model, then compares to the input actions; behavioral FDS = `1 - action_F1` (`tools/fds_harness.py` `behavioral_axis`, `compute_fds`). Caveat: IDMs are game-specific — VPT is Minecraft-only, so a new genre needs its own IDM or the model's policy head (`docs/games-wmlbench-proposal.md` §3 table, §6 risk 3).
- **Training/inference approaches referenced:** fine-tuning an **action adapter** (~4.2M params) on a frozen 1.3B base using delirium's Rolling-Forcing recipe (`.tickets/15-fds-vs-delirium-rf-endpoint.md` "New target (Path A)"); action-conditioning as gated tokens appended to T5 text context, consumed via cross-attention behind a zero-init scalar gate (`.memory/delirium-poc-learnings.md` §1); **DMD distillation** to few denoising steps, tracked via `dmdnorm` not loss value (`.memory/delirium-poc-learnings.md` §5).
- **Hard-won output-interpretation rules:** need ≥128 frames for the IDM (32-frame clips give F1≈0 even on real frames); an F1 of exactly 0.000 is usually degenerate (driver loss, action-empty episode, or OOD seed) not a real result; recorded-ceiling reference ~0.457 dense / ~0.196 sparse (`tools/README.md` "Output interpretation"; `docs/spike08-minecraft-harness-findings.md`).

## Generative Media Pipeline Aspects

- **Delirium sibling PoC = the generator/serving side** of the same domain this project *measures*: a real-time, browser-playable world model forking TencentARC Rolling Forcing, a **Wan2.1-T2V-1.3B causal DiT**, DMD-distilled to 5 steps, running ~14fps @ 480×640 on AWS Trainium2 (`.memory/delirium-poc-learnings.md` "What delirium is"). It serves RF-1.3B (Trn2 and single NVIDIA GPU via `gpu/serve_gpu.py`) and Matrix-Game-3.0 5B (4×H100) over SSE streaming endpoints — candidate models-under-test for the FDS harness (`.memory/delirium-poc-learnings.md` §2).
- **Action-conditioning / adapter design (LoRA relevance):** action steering carried by lightweight action modules; a **LoRA on attention (r32 q/k/v/o ActionDMD LoRA) was counterproductive** — degraded output to "a grainy blob," disabled by default — evidence for keeping action adapters minimal (`.memory/delirium-poc-learnings.md` §1). Coarse temporal granularity: one action vector per ~21-frame generated segment, not per frame (`.memory/delirium-poc-learnings.md` §1).
- **Serving/throughput realities:** RF-1.3B is memory-bandwidth-bound (~4–6% MFU); a hard fps cliff at T=5≈14fps vs T=4≈5–6fps (a neuronx-cc tiling artifact, not smooth step→fps); Neuron/Trainium is viable but engineering-costly vs the g5/A10G GPU path (`.memory/delirium-poc-learnings.md` §3, §7).
- **Hosting/workflow for the benchmark itself:** two validated GPU run methods — **EC2+SSM** (primary for one-person short spikes: no ml. markup, warm reuse) and **SageMaker Training Jobs** (fallback for repeated/HPO/CI/strict-repro; digest-pinned DLC, job-scoped billing, auto-terminate). Ticket 11 reproduced the EC2 result **bitwise** on SageMaker (`AGENTS.md` Constraints; `.tickets/11-sagemaker-runmethod-spike.md`; `tools/sagemaker/README.md`).
- **Media-gen data pipeline:** public action-conditioned gameplay datasets surveyed and shaped into a per-frame record (`frame uint8[H,W,3]`, `action float32[A]` multi-hot/analog, optional `state`/`event`, `reward`, `done`, `episode_id`) with whole-episode splits to avoid temporal leakage (`docs/games-wmlbench-initial-test.md` §1–2). Current in-flight work trains on **CrossFPS** (Call-of-Duty gameplay, HF `zizhaotong/CrossFPS-train`) whose real parquet schema uses raw gamepad columns (`j_left`/`j_right` sticks + `left_thumb`/`right_thumb`/`left_trigger`/`south`...), contradicting the dataset card (`.tickets/15-fds-vs-delirium-rf-endpoint.md` "Real-data schema").
- **AWS-deployability tiers (media-gen model menu):** self-hostable today = Cosmos 3 (NIM on EKS/SageMaker), Roblox Cube, Tencent HY-World 2.0; walled = Genie 3; API-only = Runway GWM-1, Decart Oasis, World Labs, Odyssey (`.memory/world-models-synthesis.md` "The Market", "Executive Summary").

## Key Terms & Jargon

- **World model** — AI that learns interactive, physics-aware environment simulation, predicting future states from actions (`.memory/CONTEXT.md`).
- **FDS (Fidelity Divergence Score)** — live 0.0–1.0 score of how much a synthetic stream diverges from a "reality" reference; games form = oracle-referenced rollout divergence, `0.0`=perfect, `1.0`=divergent, default `0.2` retrain threshold (`.memory/CONTEXT.md`; `docs/games-wmlbench-proposal.md` §3).
- **Reality stream** — the reference a model's output is scored against; in games = the engine re-running identical inputs (deterministic ground truth), not a camera (`.memory/CONTEXT.md`).
- **Behavioral axis** — the trusted FDS component: action-following via IDM round-trip; distinct from the *reported-not-trusted* visual axis (`tools/fds_harness.py`; `docs/games-wmlbench-proposal.md` §3).
- **IDM (Inverse Dynamics Model)** — infers the action taken between consecutive frames; used to re-infer actions from generated frames for action-following F1 (`tools/fds_harness.py`; `docs/games-wmlbench-proposal.md` §6).
- **h\*** — maximum admissible horizon: the last rollout step where drift error stays under tolerance (`tools/fds_harness.py` `drift_over_horizon`).
- **Ranking reversal** — a model wins visual-quality metrics (FVD/CD-FVD) while losing action-following; the phenomenon the benchmark exists to catch (`docs/games-wmlbench-proposal.md` §1).
- **Engine oracle** — the deterministic game engine used as exact, reproducible ground truth for scoring (`docs/games-wmlbench-proposal.md` §3; `.memory/CONTEXT.md`).
- **Rolling Forcing (RF) / Wan2.1** — TencentARC causal-DiT video world-model lineage the benchmark targets and delirium serves (`.memory/delirium-poc-learnings.md`).
- **DMD distillation** — Distribution-Matching Distillation reducing denoising steps; convergence tracked by `dmdnorm`, not loss value (`.memory/delirium-poc-learnings.md` §5).
- **Genie / Cosmos / Cube** — Google's playable-world model / NVIDIA's physics-aware world-foundation platform / Roblox's 3D world-model effort (`.memory/CONTEXT.md`).
- **"Vivid dream"** — Roblox's framing: interactive video models that look real but lack interactivity/challenge/persistence; the failure the benchmark quantifies (`docs/games-wmlbench-proposal.md` "Why this matters").
