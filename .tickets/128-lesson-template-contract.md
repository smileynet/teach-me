# Refactor: Lesson template contract

## Problem

Every Python generator independently assembles full HTML pages — duplicating:
- `<head>` boilerplate (meta, importmap, blocking scripts, stylesheets)
- Script imports (5+ component imports per page)
- Mount points and data islands
- DOCTYPE, html/body wrappers

When we added `typography-prefs.js`, 15+ files needed patching. When `LayoutMode.js` was added, another 15+ patches. When `glossary.js` was missing, 6 workspace lessons were broken. The scaffold exists but generators don't consistently use it, and pages generated before new features get stale.

**Deletion test:** if we delete `assets/scaffolds/lesson.html`, the generators still produce pages (they inline their own boilerplate). The scaffold is advisory, not enforced. This is shallow — the interface (the scaffold) is nearly as complex as what it replaces.

## Solution

Formalize a **template function** that ALL generators call. Generators provide ONLY:

```python
from tools.lib.page_template import render_lesson_page

html = render_lesson_page(
    title="Blender NPR Shader Fundamentals",
    lesson_number=2,
    domain="Blender → Godot Shader Pipeline",
    reading_time=12,
    win="You can build a basic toon material...",
    body_content=content_html,  # Just the <h2>s, <p>s, <svg>s, <table>s
    glossary_data={"shader-to-rgb": "...", "npr": "..."},
    data_islands={"page-data": {...}},  # Optional extra JSON blocks
    page_type="lesson",  # lesson | reference | quiz | map | index
)
```

The template function handles:
- DOCTYPE + html + head (meta, importmap, blocking prefs script, stylesheets)
- The single `<script type="module" src="../assets/page-shell.js"></script>`
- Data islands (glossary-data, page-data)
- Body wrapper structure (lesson-meta, key-concept block)
- Closing tags

**Generators never emit `<html>`, `<head>`, `<script>`, or import statements.**

## Template Hierarchy

```
page_template.py
├── base_page(title, head_extras, body_content, data_islands, page_type)
├── render_lesson_page(title, lesson_number, domain, ..., body_content, glossary_data)
├── render_reference_page(title, domain, body_content)
├── render_quiz_page(title, questions_json, lesson_file, map_page)
├── render_map_page(title, map_data_json)
└── render_index_page(title, domains_data)
```

## Key Context

- Current: `tools/lib/preact_page.py` exists and provides SOME of this for map/index pages
- Current scaffolds: `assets/scaffolds/lesson.html` and `assets/scaffolds/reference.html` — advisory templates the agent reads before generating
- ADR 0003: "Agent-Complete Pages with Shared Asset Contract" — established that pages reference shared assets but are self-contained HTML
- The generate-topic skill (agent) currently reads the scaffold and writes a full HTML file. After this refactor, it would call the template function (or the skill guidance changes to produce only content, which a post-processing step wraps)
- For GitHub Pages: pages MUST be complete static HTML at deploy time
- Research: `.scratch/research/arch-template-data.md` (272 lines, build-time template patterns)

## Sources

- [Simon Willison: Baked Data pattern](https://simonwillison.net/2021/Jul/28/baked-data/) — data + template at build time
- [Eleventy base layouts](https://www.11ty.dev/docs/layouts/) — inheritance chain for page types
- [Jinja2 template inheritance](https://jinja.palletsprojects.com/en/3.1.x/templates/#template-inheritance) — block/extends pattern
- Current `tools/lib/preact_page.py` — already implements a subset of this pattern

## Acceptance criteria

- [ ] `tools/lib/page_template.py` provides render functions for all page types
- [ ] All Python generators call the template function (not assembling HTML directly)
- [ ] Lesson HTML files have identical boilerplate (head, scripts, structure)
- [ ] Adding a global script/component = edit template once. Regenerated pages pick it up.
- [ ] Existing pages can be regenerated via template without content loss
- [ ] `assets/scaffolds/` directory can be deleted (template is the source of truth)
- [ ] Agent skill (generate-topic) guidance updated: produce body content + data, call template

## Validation

- [ ] Regenerate one lesson via template → diff shows only boilerplate changes, content identical
- [ ] `mise run verify` passes after regenerating all examples through template
- [ ] New lesson generated by agent uses template (no manual HTML assembly)
- [ ] Remove one page's head boilerplate, regenerate → correct boilerplate restored
