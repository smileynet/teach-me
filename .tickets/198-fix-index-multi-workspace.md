# Fix index page links for multi-workspace serving

## Problem

The `lessons/index.html` page (generated by `generate_index_page.py`) lists all domains across all workspaces. But its domain card links use bare relative URLs (`ink-godot-map.html`) that only resolve if the map pages are in the same directory as the index. They aren't:

```
lessons/index.html          ← index lives here
examples/godot-gamedev/lessons/godot-gamedev-map.html  ← map is here
examples/ink-godot/lessons/ink-godot-map.html          ← and here
```

When served from project root (`--workspace .`), clicking a domain card 404s because `ink-godot-map.html` doesn't exist in `/lessons/`.

## Context

This is part of a larger problem: the project has content in `examples/{domain}/` directories but no unified serving strategy that makes the index page navigate correctly to all domains. Related:

- The server (`tools/serve.py`) supports one `--workspace` at a time
- Each workspace is self-contained (its own lessons/, reference/, maps/)
- The index page aggregates ALL workspaces but assumes flat co-location

## Relationship to workspace consolidation

A future ticket may merge `examples/` content into a single live `workspace/` directory (the README describes `workspace/` as "THE user's live learning workspace"). Once consolidated, all map pages would be in one `lessons/` directory and relative links would work naturally. This ticket should be designed to work BOTH with the current `examples/` structure AND a future consolidated workspace.

## Proposed fix

Two options (decide during implementation):

### A. Absolute paths in index (minimal change)
`generate_index_page.py` emits domain links as `../examples/{domain}/lessons/{domain}-map.html` (relative to `lessons/index.html`'s location). Works from project root serving. Breaks if index moves.

### B. Index lives WITH the maps (structural fix)
Generate index at the same level as map pages. If serving from `examples/godot-gamedev`, the index and maps are siblings in `lessons/`. For multi-workspace, generate a root index that uses correct relative paths based on the actual file layout.

### C. Serve.py multi-workspace support
Teach `serve.py` to mount multiple workspaces and rewrite the index links dynamically. Most complex, most correct.

## Acceptance criteria

- [ ] `http://host:8787/lessons/index.html` loads and shows all domains
- [ ] Clicking any domain card navigates to its map page (no 404)
- [ ] Works with `--workspace .` (project root) serving
- [ ] Works with the existing single-workspace serving (backwards compatible)
- [ ] No hardcoded absolute paths (must work on any machine)
