Spatial Shader Anatomy

Lesson 3 · Godot Toon Shaders · ~10 min read
Win: You can create a shader in Godot, assign it to a mesh, and explain what the three shader functions do.
After this lesson: You can create and apply a spatial shader in Godot, explain why NORMAL means different things in vertex() vs fragment(), and write a minimal toon shader that compiles and runs.

Setting Up a Shader in Godot

Before we discuss how shaders work, let's get one running. You'll modify it as we learn each concept.

Step 1: Create the shader file

In the FileSystem dock, right-click your shaders/ folder → Create New → Resource → Shader. Name it toon_test.gdshader. Or create a plain text file with the .gdshader extension — Godot recognizes it automatically.

Paste this minimal shader (we'll explain every line below):

shader_type spatial;

uniform sampler2D albedo_texture : source_color;

void fragment() {
    ALBEDO = texture(albedo_texture, UV).rgb;
}

void light() {
    float NdotL = dot(NORMAL, LIGHT);
    float lit = step(0.0, NdotL);
    DIFFUSE_LIGHT += ALBEDO * LIGHT_COLOR * ATTENUATION * lit;
}

Step 2: Create a ShaderMaterial

  1. Select a MeshInstance3D in your scene (e.g., a building)
  2. In the Inspector → Geometry → Material Override (or Surface Material Override for specific surfaces)
  3. Click the slot → New ShaderMaterial
  4. Click into the new ShaderMaterial → set Shader → Load → pick your toon_test.gdshader

Step 3: Assign a texture

Once the shader is assigned, you'll see Shader Parameters in the Inspector. Drag an image texture into albedo_texture. The mesh should now render with hard toon lighting — lit areas at full brightness, shadow areas completely dark.

Live editing: Godot recompiles shaders instantly when you save the .gdshader file. Edit in any text editor — changes appear in the viewport within a frame. No restart or reimport needed.

What You Just Built: The Three Functions

A Godot spatial shader has exactly three entry points. Each runs at a different stage of the GPU pipeline:

Our minimal shader omits vertex() (Godot uses defaults) and uses fragment() to set the surface color and light() to control the toon response. Let's look at each:

fragment() — Set Surface Properties

Runs once per visible pixel. Your job: tell Godot what this surface looks like before any lighting is applied.

void fragment() {
    ALBEDO = texture(albedo_texture, UV).rgb;  // Base color from texture
}

ALBEDO is the surface color that light() will receive. Think of it as painting the surface — lighting comes later.

light() — Control Lighting (The Toon Part)

Runs per-pixel, once for every light affecting that pixel. This is where toon shading lives:

void light() {
    float NdotL = dot(NORMAL, LIGHT);     // How much this pixel faces the light
    float lit = step(0.0, NdotL);          // 1.0 if facing light, 0.0 if not
    DIFFUSE_LIGHT += ALBEDO * LIGHT_COLOR * ATTENUATION * lit;
}

dot(NORMAL, LIGHT) gives a value from -1 (facing away) to +1 (facing directly at light). step(0.0, x) snaps that to exactly 0 or 1 — that hard cut is what makes it "toon."

Critical: light() is called multiple times — once per light in the scene. That's why you += to DIFFUSE_LIGHT. Using = instead means only the last light wins.

vertex() — Transform Positions

Runs once per vertex. We didn't need it for the basic shader, but you'll use it whenever you need world-space data in fragment/light:

varying vec3 world_pos;
varying vec3 world_normal;

void vertex() {
    world_pos = (MODEL_MATRIX * vec4(VERTEX, 1.0)).xyz;
    world_normal = normalize((MODEL_MATRIX * vec4(NORMAL, 0.0)).xyz);
}

A varying passes data from vertex to fragment/light — it's interpolated across the triangle. This is how you get world-space coordinates in later stages.

The Coordinate Space Trap

This table will save you hours of debugging:

VariableIn vertex()In fragment()In light()
VERTEXModel spaceView space ⚠️—
NORMALModel spaceView space ⚠️View space
LIGHT——View space
MODEL_MATRIX✓ (model→world)✓✓
The rule: In fragment() and light(), VERTEX and NORMAL are in view space (camera-relative). If you need world space, compute it in vertex() and pass it via a varying.

This is exactly the bug we hit with the triplanar shader — we applied MODEL_MATRIX to a view-space NORMAL in fragment(), which produces garbage. The fix: compute world normal in vertex() where NORMAL is still in model space.

Check Your Understanding

Exercise: A colleague wrote a toon shader but the mesh renders as plain white with a hard light/dark split — their albedo texture isn't showing up at all. They show you this:

shader_type spatial;
uniform sampler2D albedo_texture : source_color;

void light() {
    float NdotL = dot(NORMAL, LIGHT);
    float lit = step(0.0, NdotL);
    DIFFUSE_LIGHT += ALBEDO * LIGHT_COLOR * ATTENUATION * lit;
}

It compiles without errors and the lighting bands work (there's a visible light/dark split). But the texture is gone — why?

Hint

light() multiplies by ALBEDO. Where does ALBEDO get its value? What happens if nothing sets it — and what function should set it?

Answer

There's no fragment() function — so ALBEDO is never set and keeps its default value of vec3(1.0, 1.0, 1.0) (white). The toon banding works because light() still calculates NdotL correctly, but it's multiplying white by the light — producing a plain white surface with lighting variation but no texture.

The fix: add fragment() to set the surface color before lighting runs:

void fragment() {
    ALBEDO = texture(albedo_texture, UV).rgb;
}

This is the pipeline in action: fragment() declares what the surface looks like → light() illuminates what fragment() prepared. Skip a stage and the downstream stage has nothing useful to work with.

Applying This to Our Test Scene

In the test-scene project:

  1. Open scenes/shader_test.tscn
  2. Select TestSphere (or TestBox) in the scene tree
  3. In the Inspector, expand Material → Surface Material Override → slot 0 → New ShaderMaterial
  4. Click the ShaderMaterial → Shader → New Shader → paste your toon_test.gdshader
  5. Expand Shader Parameters and set albedo_texture to any texture in the project

You should see hard toon banding on the mesh — lit areas show the texture at full brightness, shadow areas are black. We'll add shadow coloring in the next lesson.
