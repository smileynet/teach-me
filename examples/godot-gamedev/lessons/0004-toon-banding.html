Toon Banding

Starting point (two-band hard cut from the previous lesson):

shader_type spatial;

uniform sampler2D albedo_texture : source_color;

void fragment() {
    ALBEDO = texture(albedo_texture, UV).rgb;
}

void light() {
    float NdotL = dot(NORMAL, LIGHT);
    float lit = step(0.0, NdotL);
    DIFFUSE_LIGHT += ALBEDO * LIGHT_COLOR * ATTENUATION * lit;
}

The Problem: Two Bands Isn't Enough

The step() shader gives you exactly two states: lit and shadow. Real toon/cel shading often needs 3-4 bands — full light, half light, shadow, deep shadow — to convey form without looking flat.

Approach A: smoothstep() — Soft Two-Band

Before adding more bands, let's fix an immediate visual problem: the hard step() edge looks jagged at oblique angles. We'll replace it with smoothstep() — same threshold concept, but with a controllable transition width that anti-aliases the shadow boundary.

Create a new file toon_smoothstep.gdshader (or modify your toon_test.gdshader from the previous lesson). Two new uniforms give us control over where the cut happens and how soft it is:

 shader_type spatial;

 uniform sampler2D albedo_texture : source_color;
+uniform float threshold : hint_range(-1.0, 1.0) = 0.0;
+uniform float softness : hint_range(0.0, 1.0) = 0.1;

 void fragment() {
     ALBEDO = texture(albedo_texture, UV).rgb;
 }

 void light() {
     float NdotL = dot(NORMAL, LIGHT);
-    float lit = step(0.0, NdotL);
+    // smoothstep(edge0, edge1, x) — 0 below edge0, 1 above edge1, smooth between
+    float lit = smoothstep(threshold - softness, threshold + softness, NdotL);
     DIFFUSE_LIGHT = max(DIFFUSE_LIGHT, ALBEDO * LIGHT_COLOR * ATTENUATION * lit);
 }

The key change: threshold sets where the shadow cut happens (0.0 = faces perpendicular to light), and softness controls how many degrees of the surface are in that transition zone. At softness = 0.0 this is identical to step(); at higher values you get an anti-aliased edge that doesn't shimmer during camera movement.

Try it: In Godot's Inspector, find the ShaderMaterial → Shader Parameters section. Drag the softness slider to 0.0 → identical to step() (hard edge). Drag it to 0.5 → smooth gradient. The sweet spot for toon is usually 0.02–0.05 (barely visible softening that avoids aliasing). Look at the shadow edge on the mesh — that's where the difference shows.

This solves edge quality, but we still have only two states: lit and shadow. For the multi-band look that actually conveys form, we need a different approach entirely.

Pros: Simple, two uniforms, anti-aliased edge
Cons: Still only two bands (lit/shadow). Can't do 3+ levels.

Approach B: Modulo Trick — N Configurable Bands

The smoothstep approach gave us edge control, but it's still fundamentally binary — lit or shadow. For the anime/cel look with distinct steps of brightness conveying rounded form (highlight → midtone → shadow → deep shadow), we need to quantize continuous lighting into N discrete levels.

This is the clever bit from FlexibleToonShaderGD. One line of math snaps any continuous value to N discrete bands.

Create a new file toon_bands.gdshader. The shader structure is identical to before — all the new behavior lives in light(), where three uniforms control banding and four lines do the quantization:

shader_type spatial;

uniform sampler2D albedo_texture : source_color;
uniform int bands : hint_range(1, 8) = 3;
uniform float wrap : hint_range(-1.0, 1.0) = 0.0;
uniform float steepness : hint_range(0.5, 4.0) = 1.0;

void fragment() {
    ALBEDO = texture(albedo_texture, UV).rgb;
}

void light() {
    float NdotL = dot(NORMAL, LIGHT);

    // Combine lighting factors
    float diffuse_amount = NdotL + (ATTENUATION - 1.0) + wrap;
    diffuse_amount *= steepness;

    // THE MODULO TRICK — snaps to nearest band
    float cuts_inv = 1.0 / float(bands);
    float stepped = clamp(
        diffuse_amount + mod(1.0 - diffuse_amount, cuts_inv),
        0.0, 1.0
    );

    DIFFUSE_LIGHT = max(DIFFUSE_LIGHT, ALBEDO * LIGHT_COLOR * stepped);
}
Why max() instead of +=? Toon shading uses discrete brightness bands. With +=, two lights each contributing "fully lit" gives 2.0 — blowing out the image. max() means each light can only raise brightness to its own level, never beyond. The brightest single light wins at each pixel.
Where did ATTENUATION go? It's baked into diffuse_amount via + (ATTENUATION - 1.0). For a point light at full range, ATTENUATION=1.0 and the term adds 0. As distance increases, ATTENUATION drops below 1.0, making diffuse_amount smaller — which pushes the pixel into a darker band. Same effect, different mechanism.

How the modulo trick works

The expression mod(1.0 - x, cuts_inv) gives you the distance from x to the next band boundary above it. Adding that distance to x snaps it up to that boundary. The result: every value between two boundaries gets the same output — discrete steps.

The uniforms explained:

  • bands — number of brightness levels (1 = flat, 2 = classic toon, 3-4 = anime style)
  • wrap — shifts the shadow terminator. Positive = more lit area, negative = more shadow.
  • steepness — compresses the bands. Higher = bands bunch toward the light-facing side.

Try it: In the Inspector's Shader Parameters, set bands = 2 for classic cel. Set bands = 4 for anime. Adjust wrap to move where shadow starts. These are live sliders — drag them and watch the viewport update instantly.

Pros: N bands from one integer uniform. No texture needed. Branchless. Fast.
Cons: Bands are evenly spaced — you can't make band 1 wider than band 2. No artistic control over shape.

Approach C: Curve Texture — Artist-Paintable Ramp

The modulo trick gives us N bands cheaply, but they're all the same width. What if you want a narrow specular highlight, a wide midtone region, and a sharp drop to shadow? That requires arbitrary control over the brightness curve — and the simplest way to get that is to just... paint it.

This is what eldskald's cel shader uses. Instead of math deciding the bands, a 1D texture (gradient) maps NdotL to brightness. The lookup texture IS your art direction — whatever shape you paint into it becomes the lighting response.

Create a new file toon_ramp.gdshader. Notice how light() becomes simpler — the complexity moves from code into the texture asset:

shader_type spatial;

uniform sampler2D albedo_texture : source_color;
uniform sampler2D diffuse_ramp : hint_default_white;

void fragment() {
    ALBEDO = texture(albedo_texture, UV).rgb;
}

void light() {
    float NdotL = dot(NORMAL, LIGHT);

    // Remap NdotL from [-1,1] to [0,1] for texture lookup
    float ramp_uv = NdotL * 0.5 + 0.5;

    // Sample the ramp — the texture IS the lighting
    float lit = texture(diffuse_ramp, vec2(ramp_uv, 0.0)).r;

    DIFFUSE_LIGHT = max(DIFFUSE_LIGHT, ALBEDO * LIGHT_COLOR * ATTENUATION * lit);
}

Setting up the ramp texture in Godot

New concept — GradientTexture1D: A texture resource generated from a Gradient. Instead of an image file, you define color stops (position + color) and Godot generates a 1D lookup table. Shaders sample it like any texture, but you "paint" the values procedurally in the editor. Docs: GradientTexture1D
  1. In the ShaderMaterial, click diffuse_ramp → New GradientTexture1D
  2. Click the new texture → edit the Gradient resource
  3. Add color stops: white on the right (lit), black on the left (shadow)
  4. For toon: make the transition sharp (two stops close together)
  5. For 3 bands: add a mid-grey stop in the middle with sharp transitions on each side
This is the most powerful approach. The gradient can encode any shadow shape — hard steps, smooth ramps, asymmetric transitions, even colored shadows (sample .rgb instead of .r to tint shadows differently from lit areas). The curve IS your art direction.

To make it scene-wide (all materials share one ramp), declare it as a shader global. This is the key architectural decision — instead of each material carrying its own ramp, every toon-shaded object references the same curve. One change in Project Settings shifts the mood of the entire scene:

New concept — shader globals: A global uniform is declared in the shader but set once in Project Settings → Shader Globals. Every material that references it gets the same value — no per-material setup. Changes propagate instantly across the entire scene. Docs: Shader Globals 
global uniform sampler2D diffuse_ramp;

Then set it once in Project Settings → Shader Globals. Every material using this shader gets the same ramp. Change the ramp and the entire scene's mood shifts.

Pros: Total artistic control. Non-uniform band sizes. Colored shadows. Scene-wide via globals.
Cons: Requires creating a texture resource. Slightly more setup.

Comparison: When to Use Each

ApproachBandsArtistic controlBest for
smoothstep()2 (soft edge)Low — threshold + softnessQuick prototyping, anti-aliased toon
Modulo trickN (even)Medium — count + wrap + steepnessAnime-style multi-band, parametric control
Curve textureAny shapeHigh — paint anythingProduction art direction, scene-wide consistency

You can also combine them: use the modulo trick to quantize, then feed the result into a color ramp for tinted bands. That's what FlexibleToonShader does with its use_ramp option.

Bonus: Shadow Color Tinting

Every approach above outputs a grayscale scalar — how lit or shadowed a pixel is. But real stylized rendering uses color temperature to separate light from shadow: warm highlights feel like sunlight, cool shadows feel like ambient sky. mix() blends between two colors based on our banding output, turning a brightness value into a color shift.

Add these uniforms to any of the three shaders above — they work the same regardless of which banding approach produced stepped:

uniform vec4 shadow_color : source_color = vec4(0.2, 0.25, 0.35, 1.0);
uniform vec4 light_tint : source_color = vec4(1.0, 0.98, 0.95, 1.0);

void light() {
    float NdotL = dot(NORMAL, LIGHT);
    float stepped = /* any of the three approaches above */;

    // Mix between shadow and lit color
    vec3 toon_color = mix(shadow_color.rgb, light_tint.rgb, stepped);

    DIFFUSE_LIGHT = max(DIFFUSE_LIGHT, ALBEDO * toon_color * LIGHT_COLOR * ATTENUATION);
}

This is where the PNW Demo style comes alive — shadow_color as cool blue-grey and light_tint as warm cream gives the "overcast exterior" feel from the color script.

Check Your Understanding

Exercise: Your art director wants three different lighting styles in the same scene:

  1. Hero character — narrow bright highlight, wide midtone, sharp drop to deep shadow (non-uniform band widths)
  2. Background buildings — exactly 4 evenly-spaced bands, tunable at runtime with a single slider
  3. Distant mountains — soft two-tone (lit/shadow) with slightly fuzzy edges to avoid shimmer

For each, which of the three approaches (smoothstep, modulo, curve texture) would you use — and why can't the other two achieve it as well?

Hint

Think about what each approach gives you control over. One controls edge softness. One controls band count. One controls band shape. Match the constraint to the control.

Answer

1. Hero → Curve texture. Only approach that allows non-uniform band widths — you paint exactly where each transition falls. The modulo trick forces even spacing (can't make the highlight narrower). Smoothstep is still binary (2 states only).

2. Buildings → Modulo trick. Gives exactly N evenly-spaced bands from one integer uniform — change the bands slider at runtime. Curve texture could do it but requires painting a gradient asset for what a single integer achieves. Smoothstep can't do 4 bands.

3. Mountains → Smoothstep. Provides the soft anti-aliased edge between lit and shadow. The softness uniform controls exactly how fuzzy the transition is. Modulo gives hard discrete steps with no transition zone. Curve texture could approximate it but requires a gradient asset for what two floats already solve.
