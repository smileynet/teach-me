Color Simplification — Posterization, Palettes & Paint

Lesson 8 · Godot Toon Shaders · ~16 min read
Win: You can reduce a toon scene's color complexity using posterization (math-based), palette snapping (art-directed), and Kuwahara smoothing (paint-style), and explain when each belongs in fragment() vs post-process.
After this lesson: You understand that where you simplify color determines what gets simplified — posterizing ALBEDO in fragment() feeds simplified color into toon lighting, while posterizing as post-process reduces the final composited output. You can implement three approaches and select the right one for your art direction.

The Problem: Toon Lighting + Complex Textures = Visual Contradiction

Your toon banding shader (lesson 4) discretizes lighting into flat bands. Your outlines (lessons 6–7) add the dark borders. But look at a textured object: the lighting is flat, the borders are crisp, yet the surface colors still have all the noise, gradients, and micro-detail of a PBR texture. The result looks half-committed — stylized lighting pasted onto photorealistic surfaces.

Shipped cel-shaded games solve this by reducing color complexity to match the lighting simplification. Three approaches, each with a different aesthetic and pipeline position:

Posterization: The One-Line Color Reducer

Posterization reduces each color channel to N discrete levels. The formula is one line of math — floor(color * levels) / levels — but where you apply it changes the result dramatically.

In fragment(): Simplify Before Lighting

Apply posterization to the albedo texture before it reaches the light() function. The toon banding then operates on already-simplified colors, producing crisp flat regions where both color AND lighting are discrete:

shader_type spatial;
render_mode diffuse_toon;

uniform sampler2D albedo_texture : source_color;
uniform int color_levels : hint_range(2, 16) = 4;
uniform int shadow_bands : hint_range(2, 8) = 3;

void fragment() {
    vec3 tex_color = texture(albedo_texture, UV).rgb;

    // Posterize the albedo — reduce to N levels per channel
    float n = float(color_levels);
    ALBEDO = floor(tex_color * n) / n;
}

void light() {
    // Toon banding on the already-posterized color
    float NdotL = dot(NORMAL, LIGHT) * 0.5 + 0.5;
    float bands = floor(NdotL * float(shadow_bands)) / float(shadow_bands);
    DIFFUSE_LIGHT += ALBEDO * LIGHT_COLOR * ATTENUATION * bands;
}

This produces the most aggressive simplification — the texture is flattened before the lighting calculation. Subtle albedo variation disappears entirely, leaving only the N most dominant color regions. The toon lighting then bands across those flat regions.

As Post-Process: Simplify After Everything

Apply posterization to the final rendered frame (after lighting, outlines, everything). This preserves toon banding at full fidelity and only reduces the output color depth — the lighting transitions stay smooth within each posterized level:

shader_type canvas_item;

uniform int color_levels : hint_range(2, 32) = 6;
uniform bool enable_dithering = true;

uniform sampler2D SCREEN_TEXTURE : hint_screen_texture, filter_linear_mipmap;

// 4×4 Bayer dithering matrix (reduces visible banding)
float bayer4x4(vec2 pos) {
    int x = int(mod(pos.x, 4.0));
    int y = int(mod(pos.y, 4.0));
    float matrix[16] = float[](
        0.0, 8.0, 2.0, 10.0,
        12.0, 4.0, 14.0, 6.0,
        3.0, 11.0, 1.0, 9.0,
        15.0, 7.0, 13.0, 5.0
    );
    return matrix[x + y * 4] / 16.0;
}

void fragment() {
    vec3 color = texture(SCREEN_TEXTURE, SCREEN_UV).rgb;
    float n = float(color_levels);

    // Optional: ordered dithering smooths the banding transitions
    if (enable_dithering) {
        color += bayer4x4(FRAGCOORD.xy) / n;
    }

    COLOR.rgb = floor(color * n) / n;
    COLOR.a = 1.0;
}

Apply this to a fullscreen ColorRect in a CanvasLayer. The Bayer dithering matrix breaks up the harsh posterization bands into a stippled pattern — common in retro-styled games like Dead Cells and Return of the Obra Dinn.

When to use which pipeline stage:
  • fragment() posterization — when you want the toon lighting to operate on flat color regions. Produces the most "hand-painted" look because the lighting bands align with the color bands. Use when simplifying individual materials.
  • Post-process posterization — when you want uniform color depth reduction across the entire scene (including UI, particles, post-effects). Preserves the toon lighting calculation at full fidelity. Use for scene-wide color reduction or retro aesthetics.
Default: Start with post-process (simpler setup, consistent look). Switch to fragment() only when you need different posterization levels per material.

Palette Snapping: Art-Directed Color Reduction

Posterization reduces color uniformly — every hue gets the same number of levels. But what if your art direction calls for specific colors? A sunset scene should snap to warm oranges and purples, not arbitrary quantized values. Palette snapping maps each pixel to the perceptually nearest color in an artist-defined set.

The key insight: measuring color distance in RGB space gives wrong results because RGB doesn't match human perception. A 0.1 difference in green looks much more dramatic than a 0.1 difference in blue. The Oklab color space fixes this — equal distances in Oklab correspond to equal perceived differences. [Björn Ottosson: Oklab perceptual color space]

shader_type canvas_item;

// Artist-defined palette (set in Inspector — up to 16 colors)
uniform vec4 palette[16] : source_color;
uniform int palette_size : hint_range(2, 16) = 8;

uniform sampler2D SCREEN_TEXTURE : hint_screen_texture, filter_linear_mipmap;

// Convert linear RGB to Oklab (perceptually uniform color space)
vec3 rgb_to_oklab(vec3 rgb) {
    float l = 0.4122 * rgb.r + 0.5363 * rgb.g + 0.0514 * rgb.b;
    float m = 0.2119 * rgb.r + 0.6807 * rgb.g + 0.1074 * rgb.b;
    float s = 0.0883 * rgb.r + 0.2817 * rgb.g + 0.6300 * rgb.b;

    l = pow(l, 1.0 / 3.0);
    m = pow(m, 1.0 / 3.0);
    s = pow(s, 1.0 / 3.0);

    return vec3(
        0.2105 * l + 0.7936 * m - 0.0041 * s,
        1.9780 * l - 2.4286 * m + 0.4506 * s,
        0.0259 * l + 0.7828 * m - 0.8087 * s
    );
}

void fragment() {
    vec3 color = texture(SCREEN_TEXTURE, SCREEN_UV).rgb;
    vec3 lab = rgb_to_oklab(color);

    // Find the perceptually nearest palette color
    float min_dist = 1e10;
    vec3 nearest = palette[0].rgb;

    for (int i = 0; i < palette_size; i++) {
        vec3 palette_lab = rgb_to_oklab(palette[i].rgb);
        float dist = distance(lab, palette_lab);
        if (dist < min_dist) {
            min_dist = dist;
            nearest = palette[i].rgb;
        }
    }

    COLOR.rgb = nearest;
    COLOR.a = 1.0;
}

Set the palette uniform in the Inspector by clicking each color swatch. Start with 4–8 colors that define your scene's mood — the shader maps every pixel in the frame to the closest match. Warm palettes produce sunset feels; cool palettes produce night scenes; limited palettes (3–4 colors) produce strong graphic novel aesthetics.

Performance note: The brute-force loop (O(n) per pixel for n palette colors) is fast for small palettes (≤16). For larger palettes (32+) or higher resolutions (4K), consider precomputing a 3D lookup texture that maps RGB → palette index. The posterize-to-palette addon demonstrates this compute-shader LUT approach for production use.

Kuwahara: Paint-Style Edge-Preserving Smoothing

Posterization and palette snapping reduce the number of colors but preserve texture detail (noise, micro-gradients). What if you want the surface to look painted — broad flat strokes with hard edges between color regions, like a watercolor or gouache illustration?

The Kuwahara filter achieves this by dividing the area around each pixel into four quadrants, computing the average color and variance (how much the colors differ) in each quadrant, then outputting the average of the least variable quadrant. This eliminates fine detail while preserving sharp edges — exactly how a painter's brush fills regions with flat color but stops at boundaries. [Shadertoy: Kuwahara implementations]

shader_type canvas_item;

uniform int kernel_size : hint_range(1, 10) = 3;
uniform sampler2D SCREEN_TEXTURE : hint_screen_texture, filter_linear_mipmap;

void fragment() {
    vec2 pixel = 1.0 / vec2(textureSize(SCREEN_TEXTURE, 0));
    int radius = kernel_size;

    // Sample four quadrants around the pixel
    // For each: compute mean color and variance
    vec3 means[4];
    float variances[4];

    // Quadrant offsets: top-left, top-right, bottom-left, bottom-right
    ivec2 offsets[4] = ivec2[](
        ivec2(-1, -1), ivec2(1, -1),
        ivec2(-1, 1), ivec2(1, 1)
    );

    for (int q = 0; q < 4; q++) {
        vec3 sum = vec3(0.0);
        vec3 sum_sq = vec3(0.0);
        float count = 0.0;

        for (int x = 0; x <= radius; x++) {
            for (int y = 0; y <= radius; y++) {
                vec2 offset = vec2(
                    float(x * offsets[q].x),
                    float(y * offsets[q].y)
                ) * pixel;

                vec3 sample_color = texture(SCREEN_TEXTURE, SCREEN_UV + offset).rgb;
                sum += sample_color;
                sum_sq += sample_color * sample_color;
                count += 1.0;
            }
        }

        means[q] = sum / count;
        vec3 variance = (sum_sq / count) - (means[q] * means[q]);
        variances[q] = variance.r + variance.g + variance.b;
    }

    // Output the mean of the quadrant with lowest variance
    // (flattest region = most paint-like)
    int min_idx = 0;
    float min_var = variances[0];
    for (int q = 1; q < 4; q++) {
        if (variances[q] < min_var) {
            min_var = variances[q];
            min_idx = q;
        }
    }

    COLOR.rgb = means[min_idx];
    COLOR.a = 1.0;
}

The result: textured surfaces become flat-colored regions with sharp boundaries — the mesh looks hand-painted without any artist having to paint it. Increase kernel_size for broader strokes (more abstraction); decrease it for subtle smoothing that retains more detail.

Performance note: Kuwahara samples (kernel_size+1)² × 4 texels per pixel. At kernel_size=3 this is 64 samples; at kernel_size=8 it's 324. Keep the kernel small (2–4) for real-time use. For higher quality, the generalized 8-sector variant (Papari extension) produces smoother results with fewer blocky artifacts, but costs proportionally more.
When to use Kuwahara vs posterization: Posterization creates a poster look — distinct flat bands with abrupt transitions between them. Kuwahara creates a painted look — smooth regions that follow the image's natural structure. Posterization is cheaper and more dramatic; Kuwahara is more subtle and organic. Many games stack both: Kuwahara first (smooth the texture), posterize after (reduce the smoothed result to discrete colors).

The production stack: Shipped cel-shaded games typically combine:
  1. Toon banding in light() — discretize lighting (lesson 4)
  2. One color simplification technique — either posterization (comic look), palette (art-directed), or Kuwahara (painterly)
  3. Outlines — inverted hull + screen-space (lessons 6–7)
The order matters: Kuwahara → posterize → outline produces a different result than posterize → Kuwahara → outline. Experiment with stacking order — there's no single "correct" pipeline.

Check Your Understanding

Exercise: A colleague posterizes their toon-shaded character in fragment() with 4 color levels. The toon shadow bands are still visible — there's a clear light/dark split — but the character looks muddy and detail-less. Distinct color regions on the texture (belt, skin, armor) have collapsed into the same flat shade. Why, and what would you change?

Hint

Toon banding in light() is driven by NdotL — a geometric quantity. Does posterizing ALBEDO in fragment() affect the geometry? What does it affect?

Answer

The problem: Posterizing to 4 levels forces many distinct albedo colors into the same output bucket. Belt brown, skin tan, and armor olive all map to the same posterized value — so they become indistinguishable. The toon bands (light/dark split) survive because NdotL is geometric and independent of ALBEDO values. But the color variation within each band is gone — the surface reads as a flat uniform color with lighting on top.

The fix: Move posterization to post-process instead. Let the toon lighting operate on the full-fidelity albedo (preserving material detail), then posterize the final composited output. This simplifies the lighting's output (both albedo and light combined), keeping the relative color differences visible while still achieving the flat-color aesthetic.

This is the threshold concept: where you simplify determines what gets simplified. fragment() posterization collapses color detail that lighting can't recover. Post-process posterization works on the final image — the simplification respects whatever visual distinctions the lighting created.
