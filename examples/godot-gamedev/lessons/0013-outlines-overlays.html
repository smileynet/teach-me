Outlines & Artistic Overlays

Lesson 13 · Per-Material Toon Shading (MKToon) · ~11 min read
Win: You can add an inverted-hull outline via next_pass and shadow-weighted overlays — and explain why pipeline order matters for multiplicative vs additive effects.
After this lesson: Your toon shader has silhouette outlines (a companion shader) and hand-drawn surface texture (hatching in shadows, sketch everywhere). The mesh reads as "illustrated" rather than "rendered by computer."

The Problem: Too Clean, Too CG

← Previous: Lesson 12: Specular & Rim

Your shader now has banding, Gooch shadows, organic edges, specular stamps, and rim glow. It's feature-complete for lighting. But the surfaces are still perfectly clean CG — no silhouette outlines defining form, no surface texture suggesting a hand-drawn medium. Two finishing touches convert "shader demo" into "illustrated character":

  • Inverted-hull outlines — a second shader pass that draws visible silhouette edges around objects
  • Artistic overlays — texture patterns that add hatching in shadows and pencil grain everywhere

The Outline Shader (Companion Pass)

In Lesson 6 you learned the inverted-hull technique: inflate vertices along normals, cull front faces, render the silhouette. The MKToon variant uses a simpler model-space approach with two extra artist controls:

shader_type spatial;
render_mode unshaded, cull_front, depth_draw_opaque;

// === Outline Controls ===
uniform vec4 outline_color : source_color = vec4(0.008, 0.055, 0.086, 1.0);
uniform float outline_width : hint_range(0.0, 3.0) = 0.5;
uniform float outline_scale : hint_range(0.0, 4.0) = 1.0;
uniform float outline_clip_offset : hint_range(0.0, 1.0) = 0.0;

// Normalizing constant: converts artist-friendly width values to vertex offsets
const float TARGET_WIDTH_SCALE = 0.006;

void vertex() {
    // Compute effective width (scale multiplies, clip_offset removes thin outlines)
    float width = max(outline_width * outline_scale * TARGET_WIDTH_SCALE - outline_clip_offset * TARGET_WIDTH_SCALE, 0.0);
    VERTEX += NORMAL * width;
}

void fragment() {
    ALBEDO = outline_color.rgb;
    ALPHA = outline_color.a;
}

What's new compared to Lesson 6's version:

  • outline_scale — a global multiplier. One slider to scale all outlines up/down without changing per-material width values. Useful for LOD or zoom level.
  • outline_clip_offset — subtracts from the width. When the effective width drops to zero, the outline disappears. This lets you remove outlines from thin geometry (grass blades, wire fences) that would otherwise become solid colored blocks.
  • TARGET_WIDTH_SCALE = 0.006 — normalizes the width so artists think in "visual units" (0.5 = medium outline) rather than raw vertex offsets.
Why model-space (not view-space)? Lesson 6's view-space version scales outlines with camera distance for consistent screen pixels. The MKToon approach intentionally uses model-space — outlines get thinner as the camera moves away. For authored NPR, this is often desirable: distant objects fade into the background, foreground characters have bold outlines. It's an artistic choice, not a limitation.

Wiring the Outline via next_pass

The outline shader is a companion — it renders on the same mesh as your toon material, as a second pass. In Godot's inspector:

  1. Select your mesh with the toon ShaderMaterial applied
  2. In the material inspector, find Next Pass (below the shader parameters)
  3. Click → New ShaderMaterial
  4. Assign toon_outline_hull.gdshader
  5. Set outline_color to near-black (the default dark navy works well)

No extra MeshInstance nodes, no viewports, no post-processing. One material property wires the entire outline. (For the full inverted-hull deep-dive including view-space scaling and smooth normals, see Lesson 6.)

Artistic Overlays: Texture as Character

Outlines define form from the outside. Overlays add character to the surface itself — the difference between clean vector art and hand-inked illustration. We add two types, each with a different relationship to lighting:

Hatching (Shadow-Weighted)

Cross-hatching in traditional illustration appears in shadow areas — artists add more strokes where the surface is darker. We replicate this by weighting the overlay by 1.0 - lit_factor:

// Hatching: shadow-weighted — stronger in dark areas
if (use_hatching_dark_map) {
    float hatch = texture(hatching_dark_map, UV * hatching_scale).r;
    float shadow_weight = 1.0 - lit_factor;
    toon_color *= mix(1.0, hatch, hatching_strength * shadow_weight);
}

The mix(1.0, hatch, strength * weight) pattern is the key:

  • When weight = 0 (lit areas): result is 1.0 → no effect (surface untouched)
  • When weight = 1 (shadow areas): result is hatch scaled by strength → texture darkens the surface
  • The multiply (*=) means the overlay can only darken, never brighten

Assign any grayscale hatching texture — diagonal lines, cross-hatch patterns, or hand-drawn strokes. The hatching_scale tiles it across UVs (higher = finer detail).

Sketch (Uniform Overlay)

A subtle pencil/paper texture that appears everywhere regardless of lighting — suggesting the surface was drawn on textured paper:

// Sketch: uniform overlay — same everywhere regardless of lighting
if (use_sketch_map) {
    float sketch = texture(sketch_map, UV * sketch_scale).r;
    toon_color *= mix(1.0, sketch, sketch_strength);
}

Same mix(1.0, texture, strength) pattern, but without the shadow_weight. The sketch texture applies uniformly — a constant paper grain or pencil texture across the entire surface.

When to use which:
  • Hatching (shadow-weighted) — for ink/pen illustration styles where strokes define shadow. Typical strength: 0.1–0.3.
  • Sketch (uniform) — for pencil/charcoal/paper-grain styles where texture is part of the medium itself, not the lighting. Typical strength: 0.05–0.15 (very subtle).
  • Both together — for maximum illustrated feel. The sketch provides base texture; the hatching adds lighting-responsive detail on top.

Pipeline Order: Why Overlays Before Highlights

In the shader code, overlays multiply toon_color BEFORE specular and rim are added. This ordering is deliberate:

// 1. Compute toon_color from Gooch (lesson 10)
vec3 toon_color = mix(shadow_tint, lit_tint, lit_factor);

// 2. OVERLAYS: multiply (darken the surface texture)
toon_color *= mix(1.0, hatch, strength * shadow_weight);
toon_color *= mix(1.0, sketch, strength);

// 3. HIGHLIGHTS: add (bright on top of textured surface)
toon_color += specular;
toon_color += rim;

Why this order matters:

  • Overlays are multiplicative — they darken the existing color. If they came after highlights, they'd darken the specular stamps too (pencil marks through your highlights — wrong).
  • Highlights are additive — they add brightness on top. By applying after overlays, specular and rim "punch through" the hatching cleanly — exactly how highlights work in traditional illustration (white paint over ink).

If you accidentally put overlay code AFTER the specular += line, the hatching texture would appear inside your specular stamps — visually wrong and physically nonsensical.

Check Your Understanding

Exercise: A colleague adds a sketch overlay to their toon shader but places the overlay code AFTER the specular addition. They notice pencil-grain marks appearing inside their bright white specular stamps — the highlights look dirty. They move the overlay to a different position and it works. Explain why the original position was wrong and state the rule for ordering multiplicative vs additive effects in a toon pipeline.

Hint

Multiplicative effects darken everything they touch. If "everything" includes the specular you just added, the overlay darkens the highlight too. What would happen if you multiply BEFORE adding?

Answer

With overlay AFTER specular: toon_color += specular; toon_color *= sketch_mix; — the multiply darkens the specular stamp along with the base surface. You see pencil marks through your highlights.

With overlay BEFORE specular: toon_color *= sketch_mix; toon_color += specular; — the multiply only touches the diffuse toon color. Then specular adds clean brightness on top of the textured surface.

The rule: Multiplicative effects (overlays, textures, anything that darkens/tints) go first. Additive effects (highlights, specular, rim, any extra brightness) go last. Multiply modifies the surface; add puts light on top of it. Reversing the order causes later-added brightness to be incorrectly modified by surface texture.
