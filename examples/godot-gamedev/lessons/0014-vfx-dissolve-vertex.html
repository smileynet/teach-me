The Problem: Static Rendering in a Dynamic Game

← Previous: Lesson 13: Outlines & Overlays

Your toon shader now handles every aspect of static rendering: banding, Gooch shadows, organic edges, specular, rim, outlines, overlays. But games aren't static. Characters spawn, die, teleport, breathe, idle-wobble, and react to hits. These runtime effects need to work with the toon pipeline — not require a separate shader.

This final lesson adds two independent VFX systems that plug into the existing shader using the two functions we haven't touched yet: vertex() and the discard-capable part of fragment().

Dissolve: Pixel-by-Pixel Disappearance

A dissolve effect removes pixels progressively according to a noise texture — some areas burn away first, others survive until last. The noise map is a "burn order" where dark pixels dissolve first and bright pixels survive longest.

// Dissolve (discard pixels + border glow)
if (dissolve_enabled && dissolve_amount > 0.0) {
    if (use_dissolve_map) {
        float dissolve_val = texture(dissolve_map, UV * dissolve_map_scale).r;
        if (dissolve_val < dissolve_amount) {
            discard;
        }
        // Border glow at dissolve edge
        float border = smoothstep(dissolve_amount, dissolve_amount + dissolve_border_size, dissolve_val);
        col = mix(dissolve_border_color.rgb, col, border);
    } else {
        // No map: simple alpha fade
        ALPHA = 1.0 - dissolve_amount;
    }
}

Three things happen in sequence:

  1. Compare: sample noise texture, check if its value is below dissolve_amount
  2. Discard: if below threshold → discard removes the pixel entirely (not just transparent — gone from the depth buffer)
  3. Border: pixels just above the threshold get a colored glow via smoothstep — our threshold-smoothstep pattern from Lesson 12, applied to the dissolve edge
New concept — discard: The discard keyword stops fragment processing entirely — no color write, no depth write, no stencil write. The pixel ceases to exist. This is different from ALPHA = 0 (which still processes the fragment and may write depth). Use discard when pixels should be truly absent, not just invisible.

Why Dissolve Lives in fragment()

The dissolve runs in fragment(), before light() executes. This is critical for two reasons:

  • Performance: discarded pixels skip ALL lighting computation. With 3 lights and 90% dissolved, only 10% of pixels run light() three times — the rest are already gone.
  • Correctness: the border glow modifies ALBEDO. When light() runs on border pixels, it applies full toon banding to the border color — so the glow integrates with your scene's lighting rather than being a flat unlit overlay.
Performance note: The presence of discard in a shader disables GPU early-Z optimizations — the hardware can't skip occluded fragments because any fragment might self-discard. For objects that NEVER dissolve, consider using a separate shader without discard. The toggle-pattern (if (dissolve_enabled)) doesn't help here — the GPU sees discard exists in the compiled shader regardless of the branch.

Choosing a Dissolve Map

The noise texture determines the dissolve pattern. Different textures produce different artistic effects:

  • Perlin/Simplex noise — smooth organic burn (fire, magic fade)
  • Cellular/Voronoi — cracked-glass shatter pattern
  • Gradient ramp (vertical) — top-to-bottom or bottom-to-top wipe
  • Custom painted — artistic control over exactly which parts dissolve first (e.g., extremities before core)

Use Godot's built-in NoiseTexture2D for quick prototyping. For production, paint a custom dissolve map that matches your character's anatomy.

Vertex Animation: Breathing, Bounce, Jitter

Vertex animation displaces vertices along their normals, creating organic deformation without skeletal animation. Three modes cover common toon VFX needs:

void vertex() {
    if (vertex_animation_enabled && vertex_animation_intensity > 0.0) {
        float t = TIME;
        // Stutter: quantize time for stop-motion feel
        if (vertex_animation_stutter > 0.0) {
            t = floor(t / vertex_animation_stutter) * vertex_animation_stutter;
        }

        float wave = 0.0;
        vec3 freq = vertex_animation_frequency.xyz;

        if (vertex_animation_mode == 1) {
            // Sine: smooth breathing/pulsing
            wave = sin(t * freq.x + VERTEX.x * freq.y + VERTEX.y * freq.z);
        } else if (vertex_animation_mode == 2) {
            // Abs-sine: bouncing (always pushes outward)
            wave = abs(sin(t * freq.x + VERTEX.x * freq.y + VERTEX.y * freq.z));
        } else if (vertex_animation_mode == 3) {
            // Hash noise: chaotic jitter
            wave = vertex_noise(VERTEX + vec3(t * freq.x)) * 2.0 - 1.0;
        }

        VERTEX += NORMAL * wave * vertex_animation_intensity;
    }
}

The three modes produce different visual characters:

ModeFormulaVisualUse case
1 (Sine)sin(phase)Smooth rhythmic pulseIdle breathing, heartbeat, sway
2 (Abs-sine)abs(sin(phase))Always-outward bounceImpact reaction, inflate/deflate
3 (Noise)hash(pos + time)Chaotic jitterGlitch, corruption, magical instability
New concept — vertex displacement along normals: Using VERTEX += NORMAL * offset pushes each vertex outward (positive) or inward (negative) perpendicular to the surface. This preserves the mesh's silhouette shape and works correctly with inverted-hull outlines (the outline shader also reads NORMAL, so it deforms in sync).

The Stutter Trick: Stop-Motion in Real-Time

The most characterful feature for NPR: quantizing TIME into discrete steps so animation only updates at a chosen frame rate — while the game still runs at 60fps:

// Quantize time: floor(t / stutter) * stutter
// stutter = 0.1 → animation updates 10× per second
// stutter = 0.25 → animation updates 4× per second (very choppy)
if (vertex_animation_stutter > 0.0) {
    t = floor(t / vertex_animation_stutter) * vertex_animation_stutter;
}

The math is simple: floor(t / step) * step rounds time down to the nearest multiple of step. Between steps, t stays constant — so the wave function holds its value, creating the characteristic "frame-held" look of hand-drawn animation.

Stutter valueUpdates/secondFeel
0.0Every frame (60+)Perfectly smooth (default)
0.0520Subtle jitter — "alive" without being obvious
0.110Visible choppiness — classic anime limited animation
0.254Very stylized — paper puppet / stop-motion

Check Your Understanding

Exercise: A colleague implements dissolve but places the discard in light() instead of fragment(). Pixels do disappear when dissolve_amount increases, so it seems to work. But they notice two problems: (1) performance doesn't improve as more pixels dissolve, and (2) on some renderers the dissolve looks glitchy — flickering or showing through other objects. Explain both issues.

Hint

Think about when fragment() runs vs when light() runs. What has already happened by the time light() executes? And what does Godot's rendering pipeline expect about pixel validity after fragment() completes?

Answer

Problem 1 (performance): light() runs per-light, per-pixel, AFTER fragment(). By the time you discard in light(), the fragment shader has already computed ALBEDO, normal maps, and any other fragment() work. With 3 lights, the first light's light() call discards — but fragment() already ran for that pixel, and on multi-light setups Godot may have already evaluated prior lights. No work is saved.

Problem 2 (correctness): Godot's rendering pipeline determines depth buffer writes and shadow behavior based on what fragment() produces. A pixel that passes fragment() writes to the depth buffer. If light() then discards it, the depth write already happened — creating ghost pixels that occlude objects behind them. This is a documented Godot bug (GitHub #121077) with inconsistent behavior across Forward+, Mobile, and Compatibility renderers.

The rule: discard belongs in fragment(). Always. It's the only place where discarding has correct depth buffer behavior and actually saves downstream computation.
