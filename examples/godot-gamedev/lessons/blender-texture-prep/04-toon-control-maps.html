Authoring Toon Control Maps — Noise & Threshold

Lesson 18 · Blender to Godot Texture Prep · ~15 min read
Win: You can bake the two control maps mk_toon_lite samples — a tileable noise map that breaks up band edges and a threshold map seeded from AO that shifts shadows per-pixel — and explain exactly how each perturbs the shader's banding.
After this lesson: Control maps don't define color — they're artist instructions that tell the shader where and how to shade. Two small textures (one noise, one threshold) turn a generic toon shader into a distinctive, hand-authored look.

The Problem

Lessons 16 and 17 controlled the albedo — how many colors and which ones. But a toon shader's lighting is still generic: every band edge is a mathematically perfect line, and shadows fall exactly where N·L crosses a threshold, identically across every surface. Real stylized rendering wants per-pixel authority: band edges that wobble like an inked line, shadows that deepen naturally in creases.

mk_toon_lite.gdshader already declares uniforms for this — noise_map and threshold_map — but they ship empty. This lesson bakes both. (The shader colors its bands with gooch, not a ramp; the 1D lighting ramp is a separate mechanism, toon_ramp.gdshader, covered in its own lesson.)

Both maps perturb the band boundary

Here's the surprise: neither map defines color, and both plug into the same place — the value that gets quantized into bands. In mk_toon_lite's light() function (not fragment() — this is lighting math), the two biases are added to the lighting term just before floor():

// mk_toon_lite.gdshader — light()
if (use_noise_map)     noise_bias     = (texture(noise_map, UV * noise_scale).r - 0.5) * noise_strength;
if (use_threshold_map) threshold_bias =  texture(threshold_map, UV * threshold_map_scale).r - 0.5;
float centered = clamp(wrapped - light_threshold - diffuse_threshold_offset + 0.5 + noise_bias + threshold_bias, 0.0, 1.0);
float bands    = max(light_bands, 1.0);
float hard_band = floor(centered * bands) / max(bands - 1.0, 1.0);

Both read the texture's red channel and recenter it to [-0.5, 0.5] so a mid-gray (0.5) means "no change." Push centered up and a pixel crosses into a brighter band earlier; push it down and it stays in shadow. That's the whole mechanism — the maps just decide, per-pixel, which way to nudge.

The noise map: organic band edges

A clean toon band edge is a smooth, machine-perfect line. Feed a little noise into centered and that edge wobbles organically along its length — irregular, hand-drawn, like an inked contour with variable pen pressure. The band interior stays flat; only the seam between bands gets ragged.

The strength is deliberately small. noise_strength defaults to 0.04 and is capped at 0.25 — because it perturbs a value that's about to be floored into a few bands, even 0.25 is a strong wobble. There is no "0 to 1" knob; the effective range is 0.0–0.25.

Why the noise must be tileable. The map repeats across the surface (UV * noise_scale, and noise_scale > 1 tiles it several times). If the noise isn't seamless, you get a visible grid of hard seams wherever the tile wraps. Blender's plain 2D noise is not seamless — you have to build it so opposite edges match.

The trick is to sample the noise on a 4D torus. Map the two UV axes onto two orthogonal circles — u → (sin 2πu, cos 2πu), v → (sin 2πv, cos 2πv) — and feed those four numbers into a 4D Noise Texture. Because sine and cosine are 2π-periodic, u=0 and u=1 land on the same point, so the left and right edges (and top and bottom) match by construction. This script builds that node group and bakes the map:

import bpy, math

def build_noise_group():
    ng = bpy.data.node_groups.new("Tileable Noise 4D", "ShaderNodeTree")
    ng.interface.new_socket("Fac", in_out="OUTPUT", socket_type="NodeSocketFloat")
    nodes, links = ng.nodes, ng.links
    gout = nodes.new("NodeGroupOutput")

    texco = nodes.new("ShaderNodeTexCoord")
    sep   = nodes.new("ShaderNodeSeparateXYZ")
    links.new(texco.outputs["UV"], sep.inputs["Vector"])

    def circle(axis_out):                       # axis -> (sin 2*pi*axis, cos 2*pi*axis)
        mul = nodes.new("ShaderNodeMath"); mul.operation = "MULTIPLY"
        mul.inputs[1].default_value = 2.0 * math.pi
        links.new(axis_out, mul.inputs[0])
        s = nodes.new("ShaderNodeMath"); s.operation = "SINE"
        c = nodes.new("ShaderNodeMath"); c.operation = "COSINE"
        links.new(mul.outputs[0], s.inputs[0]); links.new(mul.outputs[0], c.inputs[0])
        return s, c

    su, cu = circle(sep.outputs["X"])
    sv, cv = circle(sep.outputs["Y"])
    combine = nodes.new("ShaderNodeCombineXYZ")
    links.new(su.outputs[0], combine.inputs["X"])
    links.new(cu.outputs[0], combine.inputs["Y"])
    links.new(sv.outputs[0], combine.inputs["Z"])

    noise = nodes.new("ShaderNodeTexNoise")
    noise.noise_dimensions = "4D"               # exposes the W input
    links.new(combine.outputs["Vector"], noise.inputs["Vector"])
    links.new(cv.outputs[0], noise.inputs["W"]) # 4th axis = cos(2*pi*v)
    links.new(noise.outputs["Fac"], gout.inputs["Fac"])
    return ng

Bake it to a 256×256 image set to Non-Color (it's data, not a picture — an sRGB decode would distort the control values). The full downloadable script adds the Emit bake and writes the file.

The threshold map: shadows from AO

The threshold map shifts where the shadow boundary falls, per-pixel. Where the map is dark, the bias is negative, so the pixel reaches shadow earlier — shadow arrives deeper and sooner into concave geometry. Convex, exposed faces stay unchanged. The terminator itself stays a crisp toon line; it just sits in a new, geometry-aware position.

You don't hand-paint this — you already have it. The Barrel_01 ARM texture's red channel is ambient occlusion: baked-in darkness in creases, gaps, and contact points. AO is exactly "how occluded is this pixel," which is exactly where you want shadow to fall first. Read the ARM red, broadcast it to a grayscale map, and you have a threshold map for free:

ARM texture (Non-Color) ─▶ Separate Color ─▶ (Red) ─▶ Combine Color (R=G=B) ─▶ threshold_map
Gotcha — AO is not shadow, and there's no strength knob. Two things to keep straight. First, read the ARM as Non-Color so the AO values aren't gamma-shifted. Second, mk_toon_lite applies the threshold at a fixed ±0.5 — there is no threshold_strength uniform. The map's own contrast is the control: a flatter AO map shifts shadows gently, a high-contrast one shifts them hard. Don't also multiply AO over the albedo (double-darkening turns creases to mud) — pick one role per channel.

Check Your Understanding

Exercise: You assign the same tileable noise map and set noise_strength to 0.0, then to 0.25 (its maximum), leaving everything else fixed. Predict the visible difference on the barrel's band edges, and explain why the shader caps the range at 0.25 rather than 1.0 — what would a value near 1.0 do to a 3-band toon look?

Hint

The noise is added to centered right before it's floored into bands. How far can you nudge a value that's about to be quantized into 3 steps before pixels start jumping the wrong band entirely?

Answer

0.0 vs 0.25: at 0.0 the noise contributes nothing — noise_bias is multiplied to zero — so band edges are perfectly clean straight lines. At 0.25 the red channel (recentered to ±0.5) contributes up to ±0.125 to centered, enough to visibly jitter the band seam: edges wobble organically along their length while the band interiors stay flat. That's the hand-drawn, inked-contour look.

Why cap at 0.25: centered is quantized into only a few bands (here 3), so each band occupies a range of about 1/3. A bias approaching 1.0 would be larger than a whole band's width — pixels would leap across two or three band boundaries at once, so instead of a wobbly edge you'd get speckled noise scattered across the whole surface, destroying the flat toon regions entirely. The 0.25 cap keeps the perturbation smaller than a band, so it only ever nudges the seam, never shatters the bands. It's an edge-breakup control, not a "add grain everywhere" control.
