# Mission: Apache Iceberg Data Lakehouse on AWS

## Why
Helping a customer build a multi-team data lakehouse on AWS using Apache Iceberg. Need to understand every component deeply enough to architect a proof of concept, speak competently to data producers and consumers, and advise on setup, operations, and limitations.

## Success looks like
- Can explain each AWS service in an Iceberg lakehouse (what it does, why it's there, what its limits are)
- Can design a PoC architecture and justify each choice
- Can speak to upstream data-producing teams about ingestion patterns and schema contracts
- Can speak to downstream data-consuming teams about query patterns, performance, and access
- Can advise on operations: compaction, snapshot management, schema evolution, access control
- Can scaffold from small (single-team PoC) to multi-team platform

## Constraints
- Learning while delivering — needs to be practical and buildable, not just theoretical
- Start small and scaffold up; don't boil the ocean
- Already conceptually familiar with ETL, schema evolution, partitioning, and AWS services at a high level
- Has read up on Apache Iceberg (conceptual, not hands-on)

## Out of scope
- Non-AWS implementations (Snowflake, Databricks-managed, GCP)
- Deep Spark/EMR tuning (for now — revisit if the PoC needs it)
- Data governance tooling beyond what's needed for the PoC
