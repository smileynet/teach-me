Variables & Conditionals

Lesson 3 · Ink + Godot · ~14 min read
Win: You can make ink stories that remember what the player did — using read counts, conditional text, variables, and alternatives to create reactive, varied prose.
After this lesson: You can track state across knots (both implicitly via read counts and explicitly via VAR), gate choices on conditions, branch prose with if/else blocks, and vary text with sequences, cycles, and shuffles.

The Story Reacts

In lesson 02's reference story, there was a line you may have noticed without fully understanding:

* {weapons || potions || maps} [Leave the market] -> tavern

This choice only appeared after visiting at least one stall. The {weapons || potions || maps} is a condition — it checks whether any of those stitches have been visited. Ink tracks this automatically: every knot and stitch has a read count — the number of times flow has passed through it.

-> village

=== village ===
The village square is quiet.
+ [Visit the well] -> well
* [Leave the village] -> END

=== well ===
{well == 1: You approach the old well for the first time.}
{well == 2: The well again. Its water looks cold.}
{well > 2: You've lost count of how often you've come here.}
-> village

Each time you divert into well, its read count increments, and the conditionals — evaluated as flow enters — pick the matching line. The read count {well} is also truthy (non-zero) once visited, so you can test it as a boolean ({well: text} = "if visited") or compare it to a number ({well > 2: text}). This is state tracking with zero setup — no declarations, no initialization. Every knot and stitch is already a counter.

Gotcha — test a knot's count from outside it: Read counts work when you enter a knot via a divert (like village → well above). A knot that loops to itself and tests its own count in the same breath won't see the value advance — the count reflects the entry, not each internal pass. Use a hub-and-spoke shape (a location you return to, diverting out to counted knots), or an explicit variable (next section) when you need a self-incrementing counter.
New concept — logical operators: || means OR (true if either side is true), && means AND (true if both sides are true), not negates. These work everywhere conditions are tested.

Conditional Content

Read counts let you detect visits. Conditional text lets you react to them — showing different prose based on whether a condition is true:

-> square

=== square ===
+ [Enter the shop] -> shop
* [Leave town] -> END

=== shop ===
{shop > 1: "Welcome back," the merchant says.|"A new face!" the merchant exclaims.}
You browse the shelves, then step back outside.
-> square

The syntax: {condition: text if true | text if false}. The | separates the two cases. If you don't need an else branch, omit it: {shop > 1: "Welcome back."} — this prints nothing when the condition is false.

Note the hub shape again: square is the hub, and you divert into shop to make its read count advance. On your second entry, shop > 1 is true and the merchant welcomes you back.

Conditional text is inline — it lives inside a line of prose. For longer branching (multiple lines, multiple conditions), you'll use if/else blocks later in this lesson.

Text That Varies

Conditional text reacts to specific conditions. But what about text that varies on its own — changing each time the player sees it, without you checking any state? Ink has four types of alternatives:

-> street

=== street ===
// Sequence (stopping): shows each in order, then sticks on the last
{I entered the shop.|I entered the shop again.|Once more, I went inside.}

// Cycle: loops forever
{&Monday|Tuesday|Wednesday|Thursday|Friday}

// Shuffle: random each time
{~rain pattered on the window|sun streamed through the glass|fog obscured the street}

// Once-only: shows each once, then nothing
{!A bell chimed as I entered.|The bell was silent this time.|}

+ [Enter again] -> street
* [Move on] -> END

The markers: no marker = stopping sequence (default), & = cycle, ~ = shuffle, ! = once-only. All use the same {...|...} syntax — the marker before the first element determines the type.

Alternatives are most useful inside loops (like the -> street loop above). A stopping sequence in a scene you visit once is just... showing text. But in a hub you return to repeatedly, it creates the illusion of a living world — each visit feels different without you writing conditional logic for each case.

New concept — the {} unifier: Every use of curly braces in ink is the story reacting to state. Read counts ({knot}), conditional text ({condition: text}), and alternatives ({a|b|c}) are all the same mechanism at different complexity levels. Think of {} as "something dynamic happens here."

Variables: Custom State

Read counts track visits. Alternatives vary text. But what about things that aren't visits — gold, inventory, relationships? For that, you declare a variable with VAR:

VAR gold = 15
VAR has_map = false
VAR player_name = "Emilia"

-> shop

=== shop ===
Welcome, {player_name}. You have {gold} gold.
+ {not has_map} [Buy the map - 8 gold]
    ~ gold = gold - 8
    ~ has_map = true
    "Here's your map."
    -> shop
+ [Leave] -> END

Three things happening here:

  1. VAR gold = 15 — declares a global variable with an initial value (the value determines the type: integer, boolean, or string)
  2. {gold} and {player_name} — prints the variable's current value inline
  3. ~ gold = gold - 8 — the ~ marker signals a logic line (assignment or operation). It means "this line changes state, don't print it."

Variables are global — accessible and modifiable from any knot. Declare them at the top of your file (before any knots) so they're initialized once.

Printing and Math

You've already seen {variable} for printing. Ink also supports basic arithmetic on logic lines:

VAR health = 100
VAR damage = 0

-> combat

=== combat ===
~ damage = RANDOM(5, 20)
~ health = health - damage
The creature strikes! You take {damage} damage. Health: {health}/100.
{health <= 0:
    You collapse. The world goes dark.
    -> END
}
* [Fight back] -> combat
* [Run away] -> escape

=== escape ===
You flee into the trees.
-> END

RANDOM(min, max) produces a random integer between min and max (inclusive on both ends — like rolling a die). Other arithmetic: +, -, *, / (integer division — 7/3 gives 2), % (remainder).

Performance note: RANDOM evaluates once when the line executes. If you need to reuse a random result, store it with ~ temp roll = RANDOM(1,6) (temp variables are covered in lesson 04).

If/Else Blocks

Inline conditionals work for short text. For longer branching — multiple lines, multiple conditions — use an if/else block:

VAR gold = 3

-> assess

=== assess ===
{
- gold >= 10:
    You're well funded. The merchant will take you seriously.
- gold >= 5:
    You have enough for basics, but nothing fancy.
- else:
    Your pockets are nearly empty. This will be difficult.
}
-> END

The block syntax: open { on its own line, each condition prefixed with -, and an optional - else: at the end. Ink evaluates top to bottom — the first matching condition wins, the rest are skipped.

This is the same {} syntax, just in block form. The key difference from inline conditionals: the opening brace is alone on its line, and each branch starts with -.

Why - again? In ink, - means different things in different contexts: a gather (after choices), a condition branch (inside {} blocks), or an else clause. Context determines meaning — if you're inside curly braces, - introduces a condition.

Conditional Choices

The final piece: choices that only appear when a condition is met. Put the condition before the choice text:

VAR has_key = false

-> door

=== door ===
The door is locked.
* {has_key} [Unlock the door]
    You slide the key in and turn. Click.
    -> END
* [Search the room] -> search
* [Give up] -> END

=== search ===
You find a rusty key under the mat.
~ has_key = true
-> door

The * {has_key} pattern means: this choice exists only when has_key is true. The player never sees it until they've found the key. This is how ink creates the classic "locked door" puzzle — the solution appears in the choice list only when you've earned it.

You can combine conditions with logical operators: * {has_key && gold >= 5} [Bribe the guard and unlock]. And remember: read counts work here too — * {search} [Try the key] appears only after visiting the search knot.

The Complete Reference Story

Here's the full reference file — a reactive shop scene where the merchant remembers your visits, you manage gold, items gate later choices, and the story's ending varies based on your preparation:

// 03_variables_and_conditionals.ink
// Reference story for Lesson 03: Variables & Conditionals
// Demonstrates: read counts, conditional text, alternatives (sequences/cycles/shuffles),
//               VAR, arithmetic, printing, if/else blocks, conditional choices

VAR gold = 15
VAR has_compass = false
VAR has_map = false
VAR shop_visits = 0

-> shop

=== shop ===
~ shop_visits = shop_visits + 1

// --- Conditional greeting: changes on repeat visits (via a counter) ---
{
- shop_visits == 1:
    The old merchant looks up as you enter. "A new face! Welcome to my humble shop."
- shop_visits == 2:
    "Back again?" The merchant smiles. "I knew you'd return."
- else:
    The merchant nods without looking up. "The usual browse?"
}

// --- Cycle: ambient description varies each visit ---
{&The shelves are dusty but well-organized.|A cat sleeps on the counter.|Wind rattles the shuttered window.|The candle flickers, casting long shadows.}

You have {gold} gold coins.

// --- Conditional choices: gated on state ---
+ {not has_compass} [Buy the compass - 5 gold]
    {gold >= 5:
        ~ gold = gold - 5
        ~ has_compass = true
        "A fine instrument," the merchant says, wrapping it in cloth.
    - else:
        "You'll need more coin for that, friend." You put it back.
    }
    -> shop

+ {not has_map} [Buy the map - 8 gold]
    {gold >= 8:
        ~ gold = gold - 8
        ~ has_map = true
        "The northern pass," he says, tapping the parchment. "Dangerous but fast."
    - else:
        "Maps don't come cheap," he shrugs. You leave it on the shelf.
    }
    -> shop

+ {has_compass || has_map} [Ask about the journey north]
    -> journey_advice

+ [Leave the shop]
    -> crossroads

=== journey_advice ===
"Heading north, are you?" The merchant leans in.
{
- has_compass && has_map:
    "With a compass AND a map? You're better prepared than most. Take the high pass — the landmarks will guide you."
- has_map:
    "The map will show you the way, but without a compass you'll struggle in fog. Stick to clear days."
- has_compass:
    "A compass keeps you on course, but without a map you won't know the landmarks. Follow the river — it leads north eventually."
}
-> shop

=== crossroads ===

// --- Shuffle: different traveler each time (random) ---
{~A merchant caravan rattles past.|A lone rider gallops by without a glance.|Two children chase a dog across the road.|An old woman sells wildflowers by the path.}

The road forks here.

* {has_map} [Follow the map north]
    The map shows a clear route through the pass. You set off with confidence.
    -> ending

* {has_compass} [Use the compass to navigate]
    The needle points true north. You follow it into the hills.
    -> ending

* [Head north without aid]
    You pick a direction and hope for the best.
    -> ending

=== ending ===
{
- has_compass && has_map:
    The journey is swift. Your map marks every turn; your compass confirms the heading. By nightfall you've cleared the pass.
- has_compass || has_map:
    The path is uncertain at times, but your {has_compass:compass|map} keeps you from losing your way entirely. You arrive tired but safe.
- else:
    You wander for two days before finding the northern road. Exhausted, hungry, but alive.
}

// --- Print remaining gold ---
{
- gold > 0:
    You still have {gold} gold coins jingling in your pocket.
- else:
    Your pockets are empty — every coin spent on preparation.
}

-> END

Play through this in Inky at least twice — once buying both items, once buying nothing. Notice how the merchant's greeting, the ambient descriptions, the available choices, the journey advice, and the ending all change based on your state. That's the power of reactive narrative.

Check Your Understanding

Exercise: Write a tavern scene where: (1) a VAR gold starts at 10, (2) the barkeep's greeting uses a stopping sequence that progresses each visit, (3) you can buy a drink for 3 gold (choice disappears when gold < 3), and (4) after buying at least one drink, a new choice appears to "Ask the barkeep for a rumor." Verify in Inky that the choices gate correctly and the greeting changes.

Hint

You need: VAR gold = 10 at top, -> tavern entry, a stopping sequence {greeting1|greeting2|greeting3} in the tavern knot, + {gold >= 3} [Buy a drink] with ~ gold = gold - 3 inside, and + {tavern > 1} [Ask for a rumor] using the read count to detect a previous purchase loop.

Answer

Any structure with these elements works:

VAR gold = 10

-> tavern

=== tavern ===
{"What'll it be?"|"You again. The usual?"|The barkeep just nods.}
You have {gold} gold.
+ {gold >= 3} [Buy a drink - 3 gold]
    ~ gold = gold - 3
    You slide the coins across. The ale is cold and bitter.
    -> tavern
+ {tavern > 1} [Ask for a rumor]
    "Word is," she whispers, "the northern pass opened up last week."
    -> END
+ [Leave] -> END

The key insight: read counts and variables work together — the read count {tavern > 1} detects you've looped (meaning you bought something), while {gold >= 3} gates the purchase on affordability. No explicit "has_bought_drink" boolean needed — the structure itself tracks the state.
