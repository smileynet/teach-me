# Mission

## Why I'm learning this

I want to build a traditional roguelike in Rust — turn-based, procedurally generated dungeon, ASCII or tile-based rendering. I've done some Rust but never a game. I want to understand the architectural patterns (ECS, game loop, procedural generation) well enough to make design decisions myself, not just copy a tutorial.

## What success looks like

I can architect a roguelike from scratch: choose the right data model for entities, generate connected dungeon levels, implement a turn-based game loop, and reason about why those choices fit the genre. If someone asks "why ECS for a roguelike?" I can explain it clearly.

## Context

- Comfortable with Rust basics (ownership, traits, enums, pattern matching)
- No game dev experience — don't know ECS, game loops, or procgen
- Not trying to ship a commercial game — learning the patterns is the goal
- Will use a Rust roguelike library (bracket-lib or rltk) for rendering, not rolling my own terminal UI
