# Mission

## Why I'm learning this

I want to build a traditional roguelike in Rust — turn-based, procedurally generated dungeon, ASCII or tile-based rendering. I've done some Rust but never a game. I want to understand the architectural patterns well enough to make design decisions myself, not just copy a tutorial.

## What success looks like

I can build a playable roguelike MVP (@ on screen, movement, generated map, FOV, monsters, combat) using appropriate Rust tools. I understand *why* the architecture is shaped the way it is — not just how to type the code.

## Context

- Comfortable with Rust basics (ownership, traits, enums, pattern matching)
- No game dev experience — don't know game loops, entity management, or procgen
- Not trying to ship a commercial game — learning the patterns is the goal
- Want to understand tradeoffs, not just follow a tutorial blindly
