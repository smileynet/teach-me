ECS Architecture for Roguelikes

Reference · Companion to Lesson 1

Core Concept

Entities are IDs. Components are data. Systems are behavior. Nothing inherits from anything. New entity types = new component combinations, zero code changes to systems.

The Three Parts

PartWhat it isExample
EntityJust an ID (u32 or u64)#42, #107
ComponentPlain data struct, no behaviorPosition{x, y}, Health{current, max}
SystemFunction that queries entities by component setmovement_system: processes (&mut Position, &WantsToMove)

Why ECS Over Inheritance

ProblemInheritanceECS
Mimic (monster that looks like item)Is it Monster or Item? Can't be both.Start with Item components, add Monster components on trigger.
Fire that melts ice wallsNeeds to know about Wall subclass.System: anything with Flammable + hit by fire → remove.
New entity typeFind the right parent, override methods.Combine existing components. No code changes.

Rust + ECS Fit

  • Ownership: World owns all components — no aliased mutable references
  • Type safety: Systems declare access — compiler enforces no conflicts
  • Performance: Same-type components stored contiguously — cache-friendly iteration

Decision Aid

"Should this be a component or a system?"

  • If it's data an entity has → component
  • If it's something that happens to entities → system
  • If it's data the world has (map, turn count) → resource (global, not per-entity)
