Roguelike Game Loop

Reference · Companion to Lesson 1

Core Concept

A roguelike loop blocks on input. Nothing happens until the player acts. The cycle is render → wait → update. This is the opposite of real-time (which runs continuously at 60fps).

The Loop

loop {
    render();                       // show current state
    let action = wait_for_input();  // BLOCK until keypress
    update(action);                 // player acts, world responds
}

Why Turn-Based Is Simpler

ConcernReal-timeTurn-based
Frame budgetMust complete in 16msNo limit — player is reading
ConcurrencySystems may run in parallelSequential — one thing at a time
Borrow checkerPainful (shared mutable state)Manageable (process in order)
When to updateEvery frame, alwaysOnly when player presses a key

Decision Aid

"Should I add ECS / architecture now?"

No. Build the MVP with plain structs + enums. Refactor when you see which patterns repeat. Architecture before gameplay is guessing.
