The nine-stage loop

An asynchronous request-reply cycle — submit returns a job handle immediately; the result comes back later on a separate channel.

  1. Client — machine / browser / team.
  2. Auth — identity + license gate.
  3. Submit API — validate + enqueue only; returns a job id. Never does GPU work in-process.
  4. Queue — durable shock absorber; survives worker restarts.
  5. Scale-to-zero GPU worker — wakes, stages weights, infers; drops to zero (or a warm floor) when idle.
  6. Weight staging — weights arrive from S3 / NFS / HuggingFace at start; never baked into the image.
  7. Infer — model execution.
  8. Output store — S3, separate from the queue broker.
  9. Progress stream — poll / SSE / WebSocket back to the client.

Six divergence axes

  • Serving substrate — custom orchestrator · Bedrock+SageMaker · ComfyUI-on-EKS
  • Target user/client — machine · human · any team
  • Progress transport — WebSocket · SSE
  • Queue — SQS FIFO · S3 tracker · DynamoDB+KEDA
  • Weight staging — S3→NVMe · HF-pull · FSxN+FlexClone
  • Scale-to-zero depth — true zero · warm-pod floor

Progress transport — pick by criteria

TransportShapeUse when
Pollingclient asks on a timer; statelessdefault; robust, survives autoscaling; latency not critical
SSEone-way server→client, auto-reconnectone-way progress (bar/logs) — the correct default
WebSocketbidirectional, heaviest lifecycleonly when the client also sends mid-job
Webhookserver calls back; no held connectionserver-to-server, long-tail jobs

Anti-patterns

  • Submit tier holds a GPU — fuses submit+worker; blocks under concurrency. Submit must validate+enqueue only.
  • Autoscaler kills a job mid-generation — need job-aware graceful drain, not blind CPU scaling.
  • Broker as result store — keep the queue (references) separate from S3 (artifacts).
  • WebSocket for one-way progress — over-engineering; SSE is the right tool.

Three honest asymmetries

  • REDACTED Bedrock path — no platform-owned worker (managed service owns it).
  • REDACTED auth — AWS-account trust, not a per-request authorizer.
  • REDACTED scale-to-zero — a warm-pod floor (KEDA minReplicaCount 1), not literal zero.
