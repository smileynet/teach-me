GDScript Fundamentals

Reference · Companion to Lesson 2

Core Concept

Attach a script to a node, extend its type, use lifecycle callbacks to give it behavior. @export for editor tweaks, @onready for node references, signals for communication.

Variable Declarations

SyntaxTypeWhen
var x = 5DynamicPrototyping only
var x: int = 5Static (explicit)Preferred — catches errors
var x := 5Static (inferred)When type is obvious from value
@export var x: float = 5.0Editor-visibleDesigner-tunable values
@onready var n := $PathDeferred initNode references ($Path)
const X = 5ConstantNever changes

Lifecycle Callbacks

CallbackRatedelta?Use for
_ready()OnceNoInit state, connect signals
_process(delta)Variable (FPS)YesVisuals, non-physics input
_physics_process(delta)Fixed (60/s)YesMovement, collision
_input(event)On eventNoOne-shot actions (jump, pause)

Signals Quick Reference

# Declare
signal health_changed(old: int, new: int)

# Emit
health_changed.emit(old_val, new_val)

# Connect (in listener's _ready)
$Player.health_changed.connect(_on_health_changed)

# Handler
func _on_health_changed(old: int, new: int) -> void:
    label.text = str(new)

Common Patterns

# Movement (CharacterBody2D)
func _physics_process(delta: float) -> void:
    var dir := Input.get_vector("left", "right", "up", "down")
    velocity = dir * speed
    move_and_slide()

# Flip sprite
if dir.x != 0:
    sprite.flip_h = dir.x < 0

Decision Aid

"_process or _physics_process?"

  • Uses move_and_slide() or collision → _physics_process
  • Visual-only (UI, particles, camera) → _process
  • Needs deterministic timing → _physics_process
  • One-shot action (not per-frame) → _input

"@export or @onready?"

  • Value set by designer in editor → @export
  • Reference to a child node → @onready
  • Never combine both on same variable (onready overwrites export)
