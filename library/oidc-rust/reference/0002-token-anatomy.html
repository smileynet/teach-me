Token Anatomy

Reference · Companion to Lesson 2

Core Concept

ID tokens prove identity to YOUR app; access tokens authorize API calls to resource servers. Never cross them. Validate every token with the 8-step checklist before trusting it.

Token Types

TokenForAudienceFormatLifetime
ID tokenIdentity (who logged in)Your appJWT (always)Minutes-hours
Access tokenAuthorization (API calls)Resource serverOpaque or JWTMinutes-hours
Refresh tokenGet new access tokensAuth server onlyOpaqueDays-months

Rule: ID token → your app. Access token → APIs. Never cross them.

JWT Structure

base64url(header) . base64url(payload) . base64url(signature)
  • Header: {"alg": "RS256", "kid": "key-id"}
  • Payload: Claims (iss, sub, aud, exp, ...)
  • Signature: RSA/ECDSA over header.payload with IdP's private key

Standard Claims

ClaimWhatValidate?
issIssuer URL✓ Must match your configured issuer
subUser's unique ID— (use as stable identifier)
audIntended audience (your client_id)✓ Must contain your app
expExpiration (Unix timestamp)✓ Must be future (allow ~60s skew)
iatIssued atOptional (detect old tokens)
nonceYour random value from auth request✓ Must match stored nonce
auth_timeWhen user entered credentialsOptional (enforce max age)
at_hashAccess token hashOptional (bind tokens together)

8-Step Validation Checklist

  1. Decode header → find kid and alg
  2. Fetch public keys from jwks_uri
  3. Verify signature with matching key
  4. Check iss matches configured issuer
  5. Check aud contains your client_id
  6. Check exp > now (with ≤60s leeway)
  7. Check nonce matches stored value
  8. Optionally check iat is recent

Production Gotchas

ProblemFix
Key rotation → sig failsRefetch JWKS when kid not in cache
Clock skew → exp rejects valid tokensAllow 30-60s leeway
Stale JWKS cacheTTL (1h) + force-refresh on kid miss
Wrong audience acceptedAlways validate aud (never skip)
Multi-tenant cross-contaminationValidate iss exactly matches expected

Decision Aid

"Token validation is failing — what do I check?"

  • Token just stopped working → check exp claim (probably expired)
  • All tokens failing after working fine → refetch JWKS (key rotation)
  • Intermittent failures → check server clock (skew beyond leeway)
  • Works for app A but not app B → check aud (wrong audience)
  • Works on one environment but not another → check iss (trailing slashes, http vs https)

"Which crate do I use?"

  • Building a login flow (web app) → openidconnect
  • Validating bearer tokens on API endpoints → jsonwebtoken + manual JWKS
  • Same as above but want auto JWKS caching → jwtk
  • Axum middleware (production, caching) → axum-oidc-layer
  • Axum middleware (simple/lightweight) → axum-jwt-oidc
