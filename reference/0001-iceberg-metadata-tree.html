Iceberg Metadata Tree

Reference · Full lesson →

One-liner: Iceberg is a file-tracking metadata tree on top of object storage — transactions, time travel, and schema evolution without a database, without rewriting data, without listing directories.

The Five Layers

LayerWhat it storesWhere it lives
CatalogPointer to current metadata fileAWS Glue Data Catalog
Metadata fileSchema, partition spec, snapshot historyJSON in S3 metadata/
Manifest listWhich manifests belong to this snapshotAvro in S3 metadata/
Manifest fileData file paths + per-file column statsAvro in S3 metadata/
Data filesActual rowsParquet in S3 data/

Why This Design

ProblemHow Iceberg solves it
S3 listing is slow at scaleManifests track files directly — no listing needed
No read isolation during writesSnapshots give MVCC — readers see a frozen file set
Schema/partition changes require rewritesVersioned specs — old files keep old schema, engine translates at read

Key Terms

TermMeaning
SnapshotFrozen view of which files belong to the table at one point in time
Manifest-level pruningSkipping data files whose column stats can't match the query predicate
Schema evolutionChanging columns without rewriting existing files — engine translates at read time
Partition specVersioned rule defining how data is split into partitions
